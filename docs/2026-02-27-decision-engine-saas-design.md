# 基于流程图编排的通用决策引擎 SaaS 产品设计文档

## 0. 开发启动版基线（2026-05-24）

### 0.1 文档状态
- 自 2026-05-24 起，本文作为后续产品开发的唯一产品文档与产品基线入口。
- `docs/superpowers/specs/` 下的专题规格与 `docs/plans/2026-03-23-decision-engine-saas-next-topics.md` 作为历史决策、细节参考和 Backlog 材料保留，不再作为与本文并列的产品依据。
- 若历史专题规格或后续清单与本文存在口径冲突，以本文为准；新的产品决策需要先回写本文，再进入技术设计或实施计划。
- 本次收口的目标是启动开发，不要求在开发前继续穷尽所有交互细节。未阻塞主链路的细节进入 Backlog，在对应开发阶段前再补充。

### 0.2 开发启动目标
- 开发启动阶段优先跑通一条可演示、可验证、可发布的端到端垂直切片，而不是一次性铺开全部节点和全部治理能力。
- 第一条垂直切片以 `注册防刷` 样板为锚点，但不提供产品内置模板；用户仍从空白画布手工搭建主流程。
- 首条主流程固定为：`Request -> Profile Query -> List(query) -> Counter -> Decision Table -> Response`。
- 该主流程保持只读，只查询画像源、名单和历史计数器统计，不包含名单写入、通知投递、HTTP 外呼或 Function 复杂转换等副作用和高风险能力。

### 0.3 P0 开发切片
P0 的验收目标是从资源准备到 Test 环境生效形成闭环：

1. 在 `数据与集成` 中查看系统内置画像源只读目录，并准备名单资源。
2. 在 `决策流` 中创建 Draft，配置 `Request / Profile Query / List(query) / Counter / Decision Table / Response` 六类节点。
3. 支持节点编辑页的“执行到此节点”和画布态整流测试，结果只保留在当前控制台会话和最近一次节点验证状态中。
4. 通过画布问题面板完成生成版本前的阻断项校验。
5. 从 Draft 生成不可变决策流版本，记录节点配置、输入输出契约、资源引用和资源指纹。
6. 在 `版本与发布` 发起 Test 发布申请；Test 申请自动通过但仍生成申请记录。
7. 发布成员在 `版本与发布` 手动发布到 Test，使该版本成为 Test 当前生效版本。
8. 关键操作进入审计日志，执行面产出结构化执行日志所需字段基础。

P0 不重新定义完整 MVP 范围。它只是开发启动顺序中的第一段，用于尽早验证控制台编辑、执行、版本、审批、发布和运行路由的核心闭环。

### 0.4 P1 补齐范围
P0 跑通后，继续补齐完整 MVP 所需能力：

- Prod 发布申请、人工审批、手动发布、回滚和发布失败处理。
- 租户全局角色、高风险能力开关、API Key 轮换和更完整的审计检索。
- `HTTP / Notify / Function / List add / List remove / List refresh_ttl` 等高级节点与副作用模式。
- `Response` 多返回结构、Function 白名单模块、节点右栏展示细节等不阻塞 P0 的交互细节。
- 完整的连接器、凭据、通道连接器和外联资源连通性测试能力。

### 0.5 Post-MVP / Backlog
以下能力不阻塞当前开发启动：

- `实时监控` 控制台页面、监控看板、指标下钻和请求明细页。
- `回放调试` 一级菜单、请求检索、历史请求轨迹、版本对比回放和异常请求转测试样例。
- 用户自定义画像源创建、字段目录维护、资源级测试和发布一致性治理。
- 产品内置模板市场、行业模板、节点生态开放。
- 名单批量导入、运营清理、大规模审计检索和更复杂的运营工作台。
- 决策表冲突分析、覆盖分析、灰度发布、A/B 实验和策略效果评估闭环。

## 1. 产品定位与目标

### 1.1 产品定位
本产品定位为 **通用决策引擎 SaaS 平台**，首发聚焦 **实时反欺诈账号风控** 场景，采用 **纯流程图引擎**（不兼容规则集子图），通过可视化编排替代“写代码改逻辑再上线”的低效流程。

### 1.2 目标与边界
- 首发目标：支持注册/登录/活动参与等链路的实时决策，降低策略迭代门槛与上线时延。
- 交付形态：先做公有云多租户 SaaS，架构预留私有化能力。
- 决策结果：完全自定义，支持返回结果与后续可扩展动作能力。
- 表达能力：低代码 + 表达式（DSL）；函数节点允许受控 JS（见权限章节）。
- 发布治理：必须支持多环境分级（Dev/Test/Prod）+ 审批发布。

### 1.3 核心价值
- 直观编排：以流程图表达决策路径，降低策略沟通成本。
- 实时可控：结构化执行日志与离线可解释能力，便于定位异常。
- 治理完备：版本化、审批、审计、回滚闭环。
- 平台化：节点能力可扩展，逐步覆盖更多业务决策场景。

## 2. 角色与场景

### 2.1 角色定义
- 风控策略师（主操作者）：设计与维护决策流、调试、提交审批。
- 研发工程师（协作者）：完成接入、维护高级节点（如函数节点）、保障稳定性。
- 风控负责人/审批人：审核变更、控制发布与回滚。

### 2.2 典型场景
- 场景 A：注册防刷。基于设备/IP/手机号画像与计数器做实时拦截。
- 场景 B：登录异常识别。结合名单命中、历史行为统计与外部接口结果判定风险。
- 场景 C：活动防作弊。通过规则编排快速上线活动期专项策略并可灰度回滚。

### 2.3 关键成功指标（建议）
- 策略发布时间：从天级降至小时级/分钟级。
- 决策链路可解释率：100% 可追溯，首版通过结构化执行日志支持离线分析。
- 实时可用性：决策服务 SLA >= 99.9%。
- 延迟目标：核心链路 p95 < 200ms（可按业务压测结果调整）。

### 2.4 后台 UI 页面信息架构（逐页）

#### 2.4.0 一级菜单与作用域原则
- MVP 控制台一级菜单按功能组织：`决策流`、`版本与发布`、`审批中心`、`数据与集成`、`组织与权限`、`审计与合规`。
- `实时监控` 保留为后续可观测能力愿景，但不进入当前阶段控制台一级菜单、空页面或建设中入口。
- 不设置独立 `项目管理` 一级菜单；项目能力并入 `决策流` 页面，用于决策流的轻量分类收纳。
- 项目不是权限、接入、运行隔离或环境策略边界，只作为决策流归属、列表筛选和阅读维度。
- 各功能页的主体对象保持稳定：
  - `决策流` 页主体为 `决策流`
  - `版本与发布` 页主体为 `决策流`
  - `审批中心` 页主体为 `审批流程记录`
  - `数据与集成` 页主体为 `资源定义与内置能力目录`
  - `组织与权限` 页主体为 `成员与权限`
  - `审计与合规` 页主体为 `操作日志`

#### 2.4.1 工作台
- 阶段定位：工作台保留为后续聚合入口愿景，不进入当前 MVP 的决策流配置发布主链路。
- 后续页面目标：让策略师和负责人在 1 分钟内识别“今天是否异常、是否有待处理发布”。
- 后续核心模块：全局健康卡片（延迟/错误率）、策略效果卡片（命中率/拦截率）、待审批摘要、告警流。
- 当前阶段边界：MVP 优先完成决策流配置、资源准备、版本发布与审批闭环，不设计工作台监控看板、指标下钻或请求明细页。

#### 2.4.2 决策流
- 页面目标：管理决策流列表、按项目轻量收纳决策流，并完成流程编排、节点配置、节点验证、整流测试和提审前自检。
- 列表模块：顶部视图包含 `所有决策流 / 按项目 / 未归类`；`按项目` 展示项目集合，进入某个项目后查看其下决策流。
- 项目收纳：项目只作为决策流分类容器；每条决策流最多属于一个项目，也可以处于 `未归类`；删除项目时，该项目下决策流默认回到 `未归类`。
- 编辑模块：大画布、节点库、三栏全屏编辑器、底部整流测试工作台、校验面板、版本对比。
- 关键交互：新建或筛选决策流 -> 进入画布 -> 拖拽建图 -> 配置节点 -> 节点级快速验证或整流测试 -> 修复问题 -> 提审。

#### 2.4.3 版本与发布
- 页面目标：围绕决策流完成版本治理、发布申请、审批、环境发布与回滚。
- 页面主体：以 `决策流` 为主体，而不是以审批单或版本混合列表为主体。
- 首页核心模块：决策流列表、环境当前生效概况、发布申请状态摘要、筛选器（项目/状态/环境）。
- 详情核心模块：`Test / Prod` 双环境卡、申请状态摘要、左侧版本列表、右侧版本详情、申请与发布记录、回滚入口。
- 页面边界：该页聚焦治理态，不展示 Draft 编辑状态；Draft 相关操作留在 `决策流` 页完成。
- 页面边界：审批与驳回等流程处理统一在 `审批中心` 完成；本页只展示与当前决策流相关的申请摘要和跳转入口。发布确认面板只在 `版本与发布` 承载。
- 关键交互：选择决策流 -> 查看 `Test/Prod` 当前生效版本与申请摘要 -> 默认打开最新版本 -> 浏览版本列表 -> 打开某个版本详情 -> 发起系统推导目标环境的发布申请 -> 跳转到审批中心处理流程 -> 审批通过后回到版本详情或环境卡进入发布确认 -> 必要时从当前环境回滚到历史版本。

#### 2.4.4 审批中心
- 页面目标：集中处理发布申请、资源变更申请、高风险权限申请等治理流程对象，避免 `版本与发布` 页面承担审批人的待办收件箱职责。
- 页面主体：以 `审批流程记录` 为主体，可按流程类型、项目、环境、状态、风险等级、申请人、审批人筛选。
- 发布申请首版边界：审批中心只处理 `通过 / 驳回`，不承载发布确认、发布失败详情或重试入口。
- 核心模块：统一列表、快速筛选（`待我处理 / 我发起的 / 已处理 / 全部`）、申请详情、通过或驳回理由、风险提示、关联 Diff、资源指纹、审批流转记录、极简发布状态摘要。
- 关键交互：从版本与发布详情页、资源详情页或权限页带过滤条件进入 -> 查看申请快照与证据摘要 -> 审批通过或驳回 -> 发布动作回到 `版本与发布` 完成。后续若启用工作台，也可从工作台待办摘要进入。

#### 2.4.5 可观测能力边界
- 页面目标：后续阶段监控线上运行状态与策略效果，快速发现偏移。
- 当前阶段：不设计 `实时监控` 一级菜单、监控看板、指标下钻或请求明细页。
- 保留基础：执行面仍产出结构化执行日志和基础执行指标，供离线分析、内部运维和未来可观测页面使用。
- 后续能力：服务指标（QPS/延迟/错误）、策略指标（命中率/空结果率）、节点耗时排行、异常趋势图与聚合维度下钻均放到增强阶段重新设计。

#### 2.4.6 数据与集成
- 页面目标：统一管理名单、HTTP 连接器、通道连接器、凭据等租户级共享资源定义；提供只读的系统内置画像源目录；同时通过独立子页 `接入设置` 管理环境级 API Key。平台内建能力如 `Counter` 不在本页单独建资源。
- 核心资源模型：
  - 总体原则：可配置资源以“资源定义”为主体，不做用户可见的资源版本；资源配置默认采用一套共享默认配置，仅在确有需要时再追加 `Dev / Test / Prod` 环境覆盖。系统内置画像源不是租户可配置资源，不提供创建、编辑、复制、凭据绑定、环境覆盖或资源级测试。
  - 系统内置画像源：MVP 只提供只读能力目录，包含手机号风险画像、IP 风险画像、设备风险画像等平台内置能力；默认全部可用，不做租户开通/未开通状态。详情页按 `基本信息 / 查询输入要求 / 字段目录 / 失败与降级说明` 组织；字段目录由系统维护，用户不可补充、隐藏或编辑。
  - 名单资源：定义为支持 TTL 的键集合，仅包含单一 key，不包含附加业务字段；资源字段聚焦 `键类型`、`规范化规则`、`默认 TTL`、引用状态与受保护状态。所有名单默认支持 `query / add / remove / refresh_ttl` 四类操作，供 `List` 节点按操作类型消费；其中 `add` 与 `refresh_ttl` 统一使用资源默认 TTL。MVP 提供单条 key 查询、新增和删除；名单数据全环境共享，不区分 Dev/Test/Prod key 集合。
  - HTTP 连接器：定义 `base URL`、认证、公共请求头、默认超时重试、安全边界与元信息注入，配置方式采用“默认配置 + 可选环境覆盖”；节点层消费连接器并填写本次调用参数，同时展示最终完整 URL 预览。
  - 通道连接器：定义为通知域专用资源，仅供 `Notify` 节点消费，不承担通用业务 API 调用；底层可复用 HTTP 连接器的环境解析、凭据绑定、默认超时重试、元信息注入、连通性测试与审计能力，但资源模型与 UI 必须独立。
  - 通道连接器配置：采用 `默认连接配置 + 可选环境覆盖` 模型，默认只需配置一套共享参数；运行时按“当前环境覆盖优先，否则回退默认配置”解析，`Prod` 允许直接继承默认配置。
  - 通道连接器详情结构：按 `基本信息 / 环境配置 / 认证与安全 / 连通性测试与审计` 四块组织。基本信息包含 `连接器名称`、`通道类型`、`供应商类型`、`用途说明`、`推荐项目标签`、`引用状态`、`受保护状态`；环境配置包含 `接入地址`、`账号标识/发送主体标识`、`绑定凭据`、`默认超时`、`默认重试策略`、`元信息注入开关`、`供应商扩展参数` 与可选环境覆盖。
  - 凭据：按“凭据对象 + 凭据版本”建模；对象承载名称、类型、用途说明、允许绑定资源类型、当前 active 版本与状态，版本承载密文内容与版本级元数据。凭据按认证模板复用，而非按通道类型拆分；同一凭据可被多个连接器复用。
  - 通知域边界：MVP 不单独维护 `通知模板` 或 `通知能力` 资源；通知内容直接定义在 `Notify` 节点中，随决策流版本进入 Diff、审批、执行日志与审计。
  - 接入设置：不进入资源列表，也不复用 `凭据` 资源模型；按 `Dev / Test / Prod` 环境管理平台对外调用 API Key。每个环境支持 `当前 Key + 备用 Key` 两把 Key，用于无中断轮换。
- 核心模块：
  - 画像源目录：只读展示系统内置画像源的基本信息、查询输入要求、字段目录、失败与降级说明。
  - 资源列表与详情页：按可配置资源类型分别展示基本信息、环境配置、引用状态、受保护状态与最近变更。
  - 名单数据维护：在名单详情页支持单条 key 查询、新增和删除；新增和删除要求 `名单数据维护` 高风险能力、二次确认并写入审计日志。
  - 凭据管理：统一管理认证信息、版本列表、active 切换、轮换记录、失效时间与审计日志。
  - 接入设置：展示基础调用地址、鉴权方式、必填参数、环境解析规则，以及各环境的当前 Key 与备用 Key。
  - 字段与约束说明：支持维护 HTTP 返回字段摘要、通道连接器的通道约束、目标字段说明与内容长度限制说明；画像源字段目录仅由系统维护，只读展示。
  - 联调测试台：支持在可配置外联资源上做连通性测试、样例请求测试，不进入正式决策流草稿；系统内置画像源不提供资源级测试。
- 关键交互：
  - 画像源：查看内置画像源目录 -> 在 `Profile Query` 节点中选择画像源 -> 通过节点验证或整流测试验证真实使用结果。
  - 可配置资源：创建资源 -> 绑定凭据 -> 配置默认连接参数与可选环境覆盖 -> 验证连通性 -> 在节点中选择消费。
  - Draft 中只负责选择和引用资源或内置能力；可配置资源本身的编辑统一在 `数据与集成` 页完成。
  - 资源列表仅显示简化引用状态：`未引用 / 仅 Draft 引用 / 已被 Test 使用 / 已被 Prod 使用`；具体影响范围在详情页展开。
  - 若资源处于受保护状态，尝试修改行为字段时直接阻止保存，并引导执行“复制为新资源”。
  - 资源变更后显示影响范围，列出受影响的决策流与环境；高风险变更需提示重新测试或重新提审。
  - 资源级连通性测试采用高权限真实测试模式，不做平台级目标白名单；执行前要求二次确认，并审计目标摘要、内容摘要、运行环境解析结果、凭据版本与供应商响应。该能力不适用于系统内置画像源。
  - 凭据轮换或停用时，自动识别依赖资源并给出两层影响提示：先展示被哪些连接器引用，再展示这些连接器被哪些 `Test/Prod` 当前生效决策流引用。
  - 环境级 API Key 只允许调用绑定环境下已发布且当前生效的决策流；调用时通过 `flow_id` 指定目标决策流，不按项目或调用方配置白名单。
  - API Key 的生成备用 Key、复制完整 Key、提升 Key、停用 Key 均要求 `API Key 管理` 高风险能力，并写入审计日志。
  - `Counter` 为平台统一托管能力，画布节点直接配置统计项；控制台不暴露底层存储实例、容量策略或热点保护资源对象。
- 治理要求：
  - 资源定义不做用户可见版本，但需保留变更历史、Diff 与审计轨迹，便于离线分析与问题追责。
  - 若资源仅被 Draft 引用，可原地修改，Draft 自动感知最新资源定义。
  - 只要资源被任一 `Test/Prod` 当前生效决策流引用，即进入受保护状态；影响运行行为的字段均不可原地修改，只能复制为新资源后在 Draft 中切换引用。
  - 决策流版本与发布申请需记录所引用资源定义的指纹，用于审批与发布一致性校验；内置画像源记录画像源标识与系统字段目录版本，不作为租户资源指纹管理。
- 高级配置：对外呼自动注入上下文元信息（如环境、请求 ID、版本号等），并显式告知客户，便于客户侧分流与追踪。

#### 2.4.7 组织与权限
- 页面目标：控制“谁能改、谁能批、谁能发”。
- 权限模型：
  - 首版只做租户全局角色和少量高风险能力开关，不做项目级、决策流级、环境级或资源类型矩阵授权。
  - 高风险能力单独授权，不默认包含在普通编辑角色中，例如：`Function 编辑`、`凭据管理`、`连接器管理`、`名单数据维护`、`API Key 管理`、`权限管理`。
- 核心角色建议：
  - 只读成员：可查看决策流、版本、审批记录、资源与审计日志，不能修改；后续若启用监控页面，也可查看监控指标。
  - 编辑成员：可创建和编辑 Draft、配置普通节点、运行测试、提交发布申请。
  - 发布成员：在编辑能力基础上，可在审批通过后执行环境发布与回滚；`Prod` 发布仍要求已有审批通过。
  - 审批成员：可处理 `Prod` 发布申请的通过或驳回；不因审批角色自动获得编辑或发布能力。
  - 管理员：管理成员、角色、高风险能力和系统级配置。
- 核心模块：
  - 成员列表：展示成员、账号、全局角色、已授予高风险能力、状态、最近活跃。
  - 角色说明：展示各角色的能力摘要，不做复杂自定义角色编辑。
  - 高风险能力：按成员授予或收回能力，所有变更要求二次确认并进入审计日志。
- 关键交互：
  - 邀请成员 -> 选择全局角色 -> 必要时授予高风险能力。
  - 高风险能力变更、凭据管理授权、API Key 管理授权、权限管理授权需触发审计并要求二次确认。
- 治理要求：
  - 管理员默认拥有高风险能力，但 UI 中仍单独展示，便于审计。
  - 普通编辑成员默认不拥有高风险能力。
  - 发布成员默认不拥有审批能力，审批成员默认不拥有发布能力；允许同一用户同时拥有二者，但不默认鼓励。
  - `Test` 发布申请自动通过，`Prod` 发布申请由审批成员处理，沿用审批中心发布申请设计。

#### 2.4.8 审计与合规
- 页面目标：提供独立操作日志查看能力，便于按条件检索和核对历史操作。
- 审计对象：
  - 决策流操作：创建、重命名、移动项目、编辑 Draft、提交发布申请、从历史版本重建 Draft。
  - 项目收纳操作：新建项目、重命名项目、删除项目、决策流移入或移出项目。
  - 版本与发布：发布到 `Test / Prod`、回滚、发布失败、资源指纹校验失败。
  - 审批中心：申请创建、自动通过、人工通过、驳回、撤销。
  - 数据与集成：资源创建、修改、复制为新资源、停用、受保护资源修改被阻止、凭据版本切换、名单 key 新增或删除。
  - 接入设置：生成备用 Key、复制完整 Key、提升 Key、停用 Key。
  - 组织与权限：邀请成员、停用成员、角色变更、高风险能力授予或收回。
  - 可观测能力：当前阶段不提供监控页面；后续若提供告警规则等配置类操作，应进入审计日志，普通指标查看不逐条记录。
- 核心模块：
  - 操作日志列表：按时间范围、操作者、操作类型、对象类型、对象名称或 ID、结果、环境、项目筛选。
  - 操作日志详情：展示基础信息、对象信息、变更摘要、失败原因或阻止原因，以及敏感信息脱敏摘要或指纹。
- 关键交互：
  - 用户按条件检索操作日志。
  - 打开日志详情查看操作结果、对象摘要与关键变更。
  - 审计页不提供跳转到决策流、版本、审批单、资源、成员或接入设置的入口；其他业务页面也不需要展示“查看审计记录”的入口。
- 合规与留痕要求：
  - 审计记录默认不可篡改，关键事件应具备明确时间戳、操作者、来源环境与对象版本号。
  - Key、凭据密文、完整请求体默认不写入日志，只记录脱敏摘要或指纹。
  - 首版不做证据包导出、留存策略配置、脱敏策略配置、权限报表或异常登录分析。

## 3. 决策流页面总体交互（核心后台 UI）

### 3.1 页面设计原则
- 大画布优先：采用 n8n 风格工作流编排体验。
- 配置聚焦：节点配置进入“覆盖式三栏全屏编辑层”，画布退到后台但不销毁。
- 实时草稿：节点内修改实时写入当前画布 Draft，不设置节点级保存按钮。
- 节点验证：所有节点统一支持“执行到此节点”，用于当前节点的快速验证。
- 整流测试：画布态支持当前草稿的整流测试，查看完整执行路径与结果。
- 环境感知：测试环境默认开启风险层，生产环境默认关闭风险层。
- 桌面优先：节点编辑态仅面向桌面宽屏，MVP 不承诺窄屏或移动端编辑体验。

### 3.2 页面布局逻辑
- 顶部：租户、所属项目、环境、版本状态、主操作（保存、测试、提审）；所属项目仅表示当前决策流归类，不作为权限或运行隔离边界。
- 中央：流程图大画布（节点与连线）。
- 右侧：可折叠节点库（搜索、分类、收藏、最近使用）。
- 底部：抽屉式工作区，承载校验与问题面板，以及仅在画布态打开的整流测试工作台。
- 节点打开：双击节点或点击“配置”时，页面切换到节点编辑态。

### 3.3 三栏全屏编辑器逻辑
- 头部：左侧展示节点类型图标与节点名称（名称可直接编辑），右侧仅保留关闭按钮；关闭后返回画布。
- 布局：三栏默认常驻、支持拖拽调宽，不设计常态折叠；当视口不足以容纳最小宽度时，直接提示“请在更大屏幕完成节点编辑”。
- 左栏（变量引用）：展示入口变量 + 当前节点所有前序可达节点输出变量。
- 中栏（节点配置）：当前节点专属配置区；所有节点均在中栏提供“执行到此节点”按钮。
- 右栏（节点验证结果）：仅展示当前节点最近一次节点验证结果，不承载整条链路轨迹、审计或线上历史请求。
- 持久化：节点内修改实时写入前端 Draft；画布层通过 debounce 自动持久化后端 Draft；仅当 Draft 仍为 dirty 时，离开画布才提示保存。
- 节点执行输入：点击“执行到此节点”时，先强制持久化当前 Draft 到后端，成功后由后端基于该 Draft 与 `Request` 节点测试样例值执行到当前节点；节点编辑态不允许临时修改输入。
- 执行前置条件：若 `Request` 节点测试样例值不足以组成合法输入，则禁止节点执行，并提示“请先在输入节点补齐测试样例值”。
- 右栏状态：仅保留 `未执行 / 执行中 / 成功 / 失败` 四种状态；未执行时展示空状态与引导，成功时展示当前节点输出，失败时展示失败原因。
- 结果时效：若当前 Draft 在最近一次节点执行后已发生变更但尚未重新执行，右栏顶部需提示“节点验证结果已失效，请重新执行”。

### 3.4 画布态整流测试工作台
- 打开方式：仅在画布态打开，进入节点全屏编辑态时自动收起；关闭测试工作台时，同时清空画布上的测试路径高亮。
- 输入来源：首次打开时，用 `Request` 节点测试样例值初始化测试输入；用户后续修改仅作用于当前画布会话内的临时样例，不回写 `Request` 节点测试样例值与 Draft。
- 布局：采用横向三列结构，不使用 Tab。
- 左侧（测试输入）：编辑本次整流测试样例；支持一键“重置为输入节点测试样例值”。
- 中间（执行节点列表）：按真实执行顺序展示本次经过的所有节点，列表项包含节点名称、节点类型、执行状态与结果摘要。
- 右侧（节点执行细节）：展示当前选中节点在本次整流测试中的输入、输出、错误原因与副作用记录。
- 执行语义：整流测试基于当前 Draft 真实执行整条链路，允许产生真实副作用；测试工作台的执行结果与节点编辑态的节点验证结果彼此独立，不共享状态。
- 结果生命周期：测试输入与测试结果仅在当前画布会话内临时保留；刷新页面、离开当前画布或关闭测试工作台后失效。
- 画布反馈：整流测试完成后，画布仅高亮本次经过的节点与连线，并对失败节点标红；不显示耗时角标、不展开节点细节，也不与测试工作台做额外双向联动。
- 草稿变更：当前 Draft 一旦变更，立即清空测试工作台结果与画布路径高亮，避免旧结果与新草稿混淆。

### 3.5 值编辑器与表达式编辑器
- 统一组件：所有“值输入位”统一使用 `Value Editor`，仅支持 `Fixed` 与 `Expression` 两种模式。
- `Fixed` 模式：输入什么就是什么，按字面值原样使用，不做解析。
- `Expression` 模式：输入内容需经表达式引擎解析后再参与判断、映射或输出；引用单个变量也属于表达式。
- 统一编辑体验：进入 `Expression` 模式时，统一弹出 `Expression Editor`；编辑器采用“文本为主、结构化引用为辅”的半结构化模式。
- 变量引用：从左侧变量面板插入的是受控 token；界面显示为“节点显示名.字段路径”，但底层绑定稳定引用，不因节点改名失效。
- token 交互：token 不能进入内部编辑；单击整块选中，左右移动按整块跨过，删除/复制/剪切按整块处理。
- 函数插入：函数以普通文本模板形式插入，不做参数槽位 UI；参数区域仍按普通文本和变量 token 混合编辑。
- 错误反馈：首版仅做 `语法错误 / 类型错误 / 引用错误` 三类反馈，并同时以内联标记和错误摘要呈现。
- 统一失败语义：表达式语法错误、类型不兼容或运行时求值异常，均使当前节点进入错误态，并按节点异常策略处理。

### 3.6 变量引用规则
- 底层稳定绑定：变量引用底层统一绑定系统生成且不可编辑的稳定 `namespaceKey`，与节点显示名称解耦；界面中以显示名 token 呈现，不直接暴露 `namespaceKey`。
- 左栏组织方式：按当前节点唯一前序链路分组展示来源节点，按距离当前节点由近到远排列，不额外特判 `Request`。
- 左栏变量展示项：来源节点显示名称、节点类型、字段类型、测试样例值摘要、最近验证值与复制引用路径；`namespaceKey` 不直接暴露给用户。
- 搜索：同时匹配节点显示名与字段路径，搜索后仍保持按来源节点分组过滤，不打平成全局列表。
- `object` 规则：允许整体引用，也允许展开到叶子字段引用。
- `array` 规则：在 UI 中仅作为整体字段展示，不展开子元素路径；但表达式层允许对数组整体做基础操作，如 `length / contains / some / all`。
- 动态查询型节点可见性：
  - `Profile Query` 选定系统内置画像源后，即可基于系统维护的字段目录暴露稳定的 `payload` 字段树；执行结果只更新字段值样例，不改变该字段树来源。
  - `HTTP` 节点未执行前仅暴露稳定外层壳 `ok / statusCode / body`；执行到该节点后，再用最近一次成功执行结果刷新 `body` 的详细字段树，供下游节点引用。
  - 已被下游表达式保存引用、但当前最新执行结果未观测到的详细字段，不自动删除；编辑器中标记为“当前未观测到”，避免破坏既有配置。
- 同名字段处理：不允许无命名空间引用，避免歧义与覆盖风险。
- 节点复制/克隆：新节点必须生成新的 `namespaceKey`；从历史版本导入/对比应尽量保留原 `namespaceKey`。
- 可见性约束：所有表达式只能引用入口变量与当前节点前序可达节点输出；不允许引用同节点内尚未产出的结果。
- 运行时取值语义：字段路径存在但值为空时返回 `null`；字段路径当前不存在时默认同样返回 `null`；只有后续表达式对该值做了不合法计算或类型不兼容操作，当前节点才进入错误态。

### 3.7 提审门禁（页面级）
- 有且仅有一个请求节点。
- 至少存在一个响应节点，且所有可达分支最终到达响应节点。
- 无环路、无不可达节点、无孤岛分支。
- 表达式语法和类型检查通过。
- 决策表与函数节点通过专属校验。
- 环境要求：Prod 仅允许发布已审批版本。

### 3.8 注册防刷样板配置发布链路
- 当前阶段以 `注册防刷` 作为模板级样例，用于说明控制台内从资源准备、决策流编排、节点验证、整流测试到版本发布的完整链路；该样例不进入 MVP 的内置模板功能。
- 用户仍从空白画布创建决策流，手工搭建主流程：`Request -> Profile Query -> List(query) -> Counter -> Decision Table -> Response`。
- 主流程保持只读，只查询画像源、名单和历史计数器统计，不包含名单写入、通知投递或其他真实副作用。
- `Profile Query`、`List`、`Counter` 只产出事实数据；`Decision Table` 集中完成最终风险判定，输出 `decision`、`risk_level`、`reason_codes`、`message_key` 等字段。
- `Response` 默认使用单一返回结构，映射统一响应字段，例如 `decision`、`risk_level`、`reason_codes`、`message`、`trace_id`；多返回结构仅在用户显式升级时启用。
- 名单必须先在 `数据与集成` 准备完成；画像源来自系统内置只读目录。节点编辑器只引用已有名单或内置画像源，不提供资源创建、凭据绑定或资源级测试的旁路入口。
- 配置完成校验采用双层呈现：画布底部问题面板负责全局阻断项，节点编辑页右栏负责当前节点最近一次验证结果。
- `HTTP`、`Notify`、`Function` 与 `List add/remove/refresh_ttl` 作为高级节点或可选副作用扩展，不进入注册防刷主线。

## 4. 节点规范（11 类节点）

> 统一约定：所有节点均有名称、描述、输入声明、对下游可见的输出模型、异常策略、审计日志开关；但并非所有节点都要求在配置时显式声明完整输出字段。

### 4.1 请求节点（Request）
- 功能：定义输入 Schema，作为流程入口。
- UI：
  - 画布内全流程唯一，固定为左侧入口节点，不支持复制；删除或重建需触发全流程引用校验。
  - 中栏采用树形 Schema 编辑器，支持 `object` 与 `array` 嵌套；字段项包含 `字段名 / 类型 / 必填 / 测试样例值 / 描述`。
  - `测试样例值` 仅服务控制面的节点验证与整流测试初始化，不参与线上运行时的请求补齐。
  - 顶部提供 `导入 JSON 样例` 与 `新增字段`；样例导入进入 Diff 预览模式，同时生成/更新 Schema 与 `测试样例值`，确认后写入草稿。
  - `测试样例值` 仅允许字面量；`object` 通过子字段逐层形成样例，`array` 作为整体值填写，不在 Schema 编辑器内逐项展开。
- 校验：
  - 有且仅有一个请求节点。
  - 后续节点仅可引用已声明字段；字段改名、删除、类型变更时，需即时标记受影响的下游引用。
  - 未声明字段不进入可引用变量空间。
  - 若存在无 `测试样例值` 的必填字段，则允许保存草稿，但会阻止节点执行；整流测试仍可由用户在测试工作台中临时补齐后运行。
- 运行：
  - 入口先做请求校验，生成两份数据：`rawRequest` 与 `request`。
  - `rawRequest` 保留完整原始入参，仅用于离线分析与审计；`request` 为校验后的正式输入，仅此命名空间可被后续节点引用。
  - 入参中存在未声明字段时不直接报错，但需在调试与问题面板提示这些字段已被忽略出变量空间；Schema 校验失败则走系统错误响应。

### 4.2 响应节点（Response）
- 功能：作为分支终点节点，将当前分支结果映射到同一份流级共享输出契约并返回。
- UI：
  - 输出契约为流级共享资源，入口位于任意 `Response` 节点内部，而非全局工具栏；多个 `Response` 节点共享同一份输出契约，不各自维护私有 schema。
  - 节点编辑器顶部固定两个视图：`当前节点赋值` 与 `共享输出契约`，始终区分“当前出口映射”与“全局输出契约编辑”。
  - 共享输出契约默认从 `单一返回结构` 起步；只有用户显式执行 `升级为多返回结构`，才切换为“公共字段 + 返回结构”的根层组织模型。
  - 首次升级为多返回结构时，需复用现有单一结构：用户先为当前结构命名，再从既有字段中勾选哪些提升为 `公共字段`；未勾选字段保留在该初始返回结构中。后续新增第三个及以上返回结构时，不再重复该迁移流程。
  - `共享输出契约` 在单一模式下就是一份普通树形输出 schema 编辑器，仅维护字段名、类型、必填与说明；在多返回模式下，主体分为 `公共字段` 与 `返回结构列表`。
  - `当前节点赋值` 在单一模式下，直接对整份共享输出契约逐字段赋值；在多返回模式下，当前节点必须且只能绑定一个返回结构，然后在同一页内连续展示 `公共字段赋值` 与 `当前返回结构字段赋值` 两段。
  - 字段映射统一使用 `Value Editor(Fixed/Expression)`；默认命名使用序号型节点名，如 `响应 1`、`响应 2`，由用户自行改为业务语义名称。
  - 在多返回模式下，画布卡片与节点编辑头部额外展示当前绑定的返回结构标签；节点显示名不因绑定结构变化而被系统强制改写。
  - 一个返回结构允许被多个 `Response` 节点复用；删除返回结构前，必须先解除所有 `Response` 节点对它的绑定。
  - 在 `共享输出契约` 中新增、删除、改名、改类型、切换必填状态，或在 `公共字段` 与结构字段间迁移字段时，页面需实时提示受影响的 `Response` 节点数量与名称，并将这些节点标记为 `待修复`。
- 校验：
  - 分支终点必须是响应节点。
  - 同一决策流内所有 `Response` 节点遵循同一流级输出契约。
  - 单一模式下，每个 `Response` 节点都必须对该单一结构完成完整映射，不允许只填写部分字段再将其余字段留空由平台默认补齐。
  - 多返回模式下，当前节点必须先绑定一个返回结构；公共字段与该返回结构字段均需完成完整映射。
  - 公共字段与返回结构字段均按完整路径校验；允许不同返回结构下重复出现同名路径，如 `data`，但它们属于不同返回结构命名空间。
  - 必填字段缺失映射、表达式失败或类型不匹配均视为节点错误；受共享契约变更影响而待修复的 `Response` 节点阻止提审与版本生成。
- 运行：
  - 命中后返回结果并结束主流程。
  - 字段彼此独立求值，表达式只能引用入口变量与前序可达节点输出。
  - 返回结构仅作为契约与执行日志元数据使用，不强制要求对外响应体存在固定判别字段。

### 4.3 派生变量节点（Derived Variables）
- 功能：定义多个可复用的命名中间变量，承接“复杂、可复用、需要命名”的计算。
- UI：
  - 中栏采用纵向平铺的变量表单列表，而非表格；每项仅包含 `变量名`、`表达式`、`说明（可选）`。
  - 顶部提供 `新增变量`；每项支持 `复制 / 删除 / 拖拽排序`，排序仅影响阅读顺序，不代表执行顺序。
  - 表达式通过统一 `Expression Editor` 编辑，不提供对象字段级可视化搭建器。
  - 类型不要求用户显式填写，仅作为系统推断结果参与引用提示与校验。
- 校验：
  - 变量名唯一。
  - 所有变量彼此独立，只能引用上游变量，不能引用同节点内其他派生变量。
  - 表达式语法错误或推断出的明显类型冲突需即时提示。
- 运行：
  - 单个变量可返回标量、对象或数组，并写入当前节点命名空间。
  - 节点内各变量独立计算；任一变量求值失败即使节点进入错误态，并按节点异常策略处理。
  - 若某个派生结果需要被另一个派生结果消费，必须拆成两个串联节点。

### 4.4 条件分支节点（Condition）
- 功能：定义多个分支条件并显式路由到不同出口。
- UI：
  - 采用纵向分支卡片列表，自上而下与节点右侧出口顺序一致；同一时刻仅展开一个分支卡片。
  - 卡片头固定展示分支序号、分支名称、出口状态（已连接/未连接/连接失效）与条件摘要。
  - 新建普通分支时默认创建一条空的标准条件行；普通分支支持复制、删除与拖拽排序，排序即命中优先级语义。
  - 节点必须包含一个显式兜底分支，兜底分支固定存在、不可删除、不可配置条件。
- 条件编辑：
  - 仅提供标准条件行与条件组，不提供独立的整行布尔表达式模式。
  - 标准条件行为 `左值 + 操作符 + 右值`，左右值统一使用 `Value Editor(Fixed/Expression)`。
  - 当同层级新增第二条及以上条件时，默认逻辑符为 `AND`，用户可切换为 `OR`。
  - 条件组最多支持两层嵌套，达到第二层后 UI 直接禁止继续新增子组。
  - 操作符按类型分组选择，首版支持数值/时间比较、文本/集合比较、布尔判断与空值判断。
- 校验：普通分支与兜底分支均必须连接到后续节点；未连接不阻止编辑，但阻止节点校验通过与提审。
- 运行：按分支顺序依次判定，首个命中分支即路由并停止继续判断；若普通分支均未命中，则进入显式兜底分支。

### 4.5 名单节点（List）
- 功能：对租户预定义名单执行 `query / add / remove / refresh_ttl` 四类操作。
- UI：
  - 中栏先选择 `操作类型`，再按模式展示后续配置。
  - `query` 模式展示 `名单资源` 与 `查询值`；`add / remove / refresh_ttl` 模式展示 `名单资源` 与 `键值`。
  - 名单资源仅包含单一 key，不提供查询字段选择。
  - `查询值 / 键值` 统一使用 `Value Editor`，默认进入 `Expression` 模式，允许切换为 `Fixed` 供调试使用。
  - 结果输出采用固定平台结构，不要求用户手工映射字段。
- 校验：
  - 名单必选。
  - `查询值 / 键值` 表达式结果必须与名单资源的 `键类型` 兼容；表达式求值失败或类型不兼容时，节点进入错误态。
- 运行：
  - 节点输出采用统一外壳：`success`、`operation`、`reason`、`key`、`hit`、`applied`、`expiresAt`、`ttlRemainingMs`；与当前操作无关的字段置空。
  - `query` 模式仅判断命中与剩余 TTL；查询值成功求出但为空、`null` 或空字符串时，按未命中处理，同时将 `reason` 记为 `empty_input`。
  - `add` 模式将 key 写入名单；`refresh_ttl` 模式将过期时间刷新为“当前时间 + 资源默认 TTL”；`remove` 模式删除 key。
  - `add / remove / refresh_ttl` 为真实副作用操作；节点验证右栏与整流测试节点详情均展示实际 key、规范化结果、执行前状态、执行结果与执行后状态，但不改变现有页面骨架或画布反馈模型。

### 4.6 画像查询节点（Profile Query）
- 功能：查询 IP/手机号风险画像。
- UI：
  - 采用查询型节点骨架，但节点本身不配置 `画像类型 + 供应商`、接入地址、凭据或环境覆盖。
  - 中栏分为 `画像源`、`查询值`、`失败策略` 三段。
  - `画像源` 直接选择系统内置画像能力；内置画像源默认全部可用，不存在租户级开通状态。
  - `查询值` 统一使用 `Value Editor`，默认 `Expression` 模式。
  - 选定画像源后，系统只读展示字段目录摘要，帮助阅读返回结构，但不参与运行时转换。
- 校验：
  - 画像源、查询值与失败策略必填。
  - 节点实例一旦选定画像源，其下游可引用的 `payload` 字段树即基于系统字段目录固定；后续切换画像源需触发下游引用校验。
- 运行：
  - 节点输出采用最小统一外壳：`success`、`degraded`、`reason`、`payload`。
  - `payload` 直接暴露内置画像源返回的原始字段结构，不做跨画像源强归一化，也不做平台二次投影。
  - 查询成功时输出 `success=true`、`degraded=false`、`reason=null`；软失败时输出 `success=false`、`degraded=true`、`reason=失败原因`、`payload=null`；若节点配置为严格失败，则节点直接进入错误态并按异常策略处理。
  - 节点验证右栏与整流测试节点详情展示画像源、查询值摘要、执行结果、失败或降级原因、耗时与原始 `payload` 摘要；不展示环境解析结果、凭据版本、资源指纹或供应商配置摘要。画布本身仍只做路径高亮与失败标红。

### 4.7 计数器节点（Counter）
- 功能：对字段做时间窗口统计（如 5m/1h/24h）。
- UI：
  - 节点内采用纵向平铺的 `统计项` 列表，而非单规则节点或表格。
  - 顶部展示 `历史窗口统计`、`结果不含当前请求` 与 `平台默认隔离到 tenant + flow + env` 等摘要，并提供 `新增统计`。
  - 每个统计项包含 `统计名称`、`统计类型`、`时间窗口`、`说明（可选）` 等公共字段；统计名称自动生成默认值，但允许手工修改。
  - `时间窗口` 采用“先选单位，再选数字”的方式，数字从固定档位中选择，不支持任意自由输入时长表达式。
  - 统计类型首版仅支持 `计次` 与 `分组去重`：`计次` 仅展示 `统计 key`，`分组去重` 额外展示 `分组 key` 与 `去重 key`。
- 校验：
  - 统计名称唯一。
  - 时间窗口配置合法；`统计 key / 分组 key / 去重 key` 均使用统一 `Expression`，但结果必须是单个可序列化值，不支持对象结果。
  - 排序仅影响阅读顺序，不影响执行语义。
- 运行：
  - `Counter` 为平台原生能力，不在资源中心单独建资源，也不向用户暴露底层存储对象。
  - 当前语义仅查询历史窗口统计结果，不将当前请求写入计数器。
  - 节点输出为按统计项名称组织的扁平对象，值为各统计项的数值结果，供后续条件判断或决策表引用。
  - 统计项默认命名统一采用 `snake_case`：`计次` 默认为 `<key_alias>_count_<window>`，`分组去重` 默认为 `<group_alias>_distinct_<dedupe_alias>_<window>`；复杂表达式则退化为通用默认名并在重名时自动追加序号。
  - 调试时展示实际求值后的 key、窗口、统计类型与返回值，不展示状态前后变化，因为该节点无副作用。

### 4.8 HTTP 请求节点（HTTP）
- 功能：调用外部 HTTP 接口补充数据。
- UI：
  - 采用“连接器定义服务边界，节点定义本次调用”的模型。
  - 中栏分为 `连接器`、`请求配置`、`运行策略`、`结果输出` 四段。
  - 连接器层定义按环境区分的 `base URL`、认证、公共请求头、默认超时重试、安全策略与元信息注入；节点层仅允许配置 `method`、相对 `base URL` 的 `path`、路径参数、query、body、非敏感业务 headers，以及受限范围内的超时重试覆盖。
  - 节点配置页需明确展示最终完整 URL 预览与最终认证/注入摘要，保证用户清楚看到实际调用目标。
  - `query / headers / body` 不使用自由 JSON 文本，而采用参数项列表配合 `Value Editor`。
- 校验：
  - 连接器配置完整且可用。
  - 节点不允许填写完整 URL；`path` 必须受连接器约束。
  - 请求参数与节点允许覆盖的运行参数需满足连接器声明的限制。
- 运行：
  - 节点主输出采用“轻外壳，重 body”的结构，仅保留 `ok`、`statusCode` 与 `body` 作为主引用路径。
  - 未执行前，下游仅能看到稳定外层壳；执行到该节点后，系统再基于最近一次成功执行结果刷新 `body` 的详细字段树，供下游节点继续引用。
  - `body` 优先按 JSON 解析并暴露结构化字段树，解析失败时退回文本；若已保存的详细字段在当前执行结果中未出现，下游引用仍然保留，只标记为“当前未观测到”。
  - 响应头、重试次数、耗时、原始请求/响应等诊断信息默认不进入可引用变量空间，而在节点验证结果、整流测试节点详情与审计日志中完整保留。
  - 异常按节点策略处理。
- 环境行为：Dev/Test 默认真实外呼，不做平台级 dry-run；建议配置幂等/去重键，发布时给出风险提示。

### 4.9 通知节点（Notify）
- 功能：配置并提交一次通知或异步投递请求。
- UI：
  - `Notify` 为单一通用节点；拖入画布后先选择 `通道类型`，再按通道动态切换配置表单。
  - 节点显式选择租户账户级共享的 `通道连接器`；连接器负责供应商地址、鉴权、默认超时重试、元信息注入与运行时环境解析，节点不直接接触明文凭据。
  - 中栏配置顺序固定为 `通道类型`、`通道连接器`、`接收目标/路由`、`通知内容`、`投递策略`。
  - 节点本身不区分环境，也不提供环境切换；运行时始终按当前决策流所在环境自动解析连接器配置，解析顺序为“环境覆盖优先，否则回退默认连接配置”。
  - `接收目标/路由` 使用普通 `Value Editor(Fixed/Expression)`，按通道分别展示字段：短信仅 `手机号`；邮件为 `to`、`cc`、`bcc`；Webhook 为可选 `相对路径`；飞书为 `目标类型` + `目标值`，其中 `目标类型` 首版仅支持 `user_id / open_id / chat_id`。
  - `通知内容` 使用专用模板文本编辑器，不复用通用表达式编辑器；正文/主题/body 中仅支持普通文本与变量 token。用户可通过“插入变量”加入前序可达字段，也可直接输入 `{{field_name}}`，识别合法后自动转为 token。
  - 模板文本编辑器中的 token 按整体处理，不允许进入内部逐字编辑；若输入包含函数、运算符、三元表达式、调用语法等复杂内容，需即时报错并提示“请先在上游节点计算”。
  - 中栏只展示静态检查结果，不做带值预览；右栏仅在执行到该节点后展示真实渲染结果与提交通知结果。
  - `投递策略` 首版仅包含 `幂等键（可选）` 与 `提交失败时的异常策略`；自定义重试/超时等供应商级策略统一放在连接器层维护。
  - 通道字段按类型差异化建模：短信首版仅 `短信正文`；邮件首版为 `主题 + 纯文本正文`；Webhook 首版固定为 `POST + application/json`，请求体采用 `JSON 模板文本` 编辑器；飞书首版仅支持应用消息模型，内容为 `文本内容`，不支持机器人 Webhook 与卡片消息。
  - Webhook 节点层不开放自定义 Header；固定 Header、鉴权与元信息注入统一在连接器层维护。
- 校验：
  - 通道类型、通道连接器、接收目标/路由必填；连接器类型必须与节点所选通道一致。
  - `接收目标/路由` 的固定值或表达式结果需满足通道字段类型要求；表达式求值失败或类型不兼容时，节点进入错误态。
  - 通知内容只允许文本与合法变量占位符；占位符必须引用当前节点前序可达变量，不允许包含复杂表达式或不存在字段；Webhook `JSON body` 还需通过 JSON 结构校验。
  - 幂等键如有配置，必须可稳定求值并满足连接器声明的长度/字符限制；提交失败时的异常策略需与节点全局异常语义保持一致。
- 运行：
  - 节点成功仅表示“已成功向供应商或连接器提交通知请求”，不表示最终送达成功。
  - 节点不等待最终送达回执；一旦提交成功即继续主流程，不向下游暴露可供引用的业务输出。
  - 若连接器不可用、鉴权失败、同步超时或供应商同步返回错误，则视为提交失败，并按节点异常策略处理；提交成功后的异步送达失败仅记录在运行态与审计中，不反向影响主流程。
  - 节点验证结果与整流测试节点详情统一分为 `配置摘要`、`目标摘要`、`渲染结果`、`提交结果` 四块，重点记录通道类型、连接器、解析后的运行环境配置、配置指纹、脱敏目标摘要、最终渲染内容快照、提交时间、任务 ID/供应商请求 ID、超时/重试摘要与失败原因，供审计、离线日志分析和运维排障使用。
- 资源治理：
  - `通道连接器` 为资源定义，不做用户可见版本；若其行为字段被 `Test/Prod` 当前生效决策流引用，则进入受保护状态，需复制为新资源后在 Draft 中切换引用。
  - 通知内容不单独资源化，而是随决策流版本一并进入 Diff、审批、执行日志与审计。
- 环境行为：Dev/Test 默认真实投递，不做平台级 dry-run；建议配置幂等/去重键，发布时给出风险提示。

### 4.10 决策表节点（Decision Table，核心）
- 功能：通过行式表格定义规则，作为关键决策中枢。
- 结构：支持定义多个输入列、多个输出列；中栏采用“列模型定义区 + 规则表格区”的分区式结构。
- 输入列规则：
  - 输入列分为 `绑定列` 与 `未绑定列`。
  - 绑定列：列头声明绑定左操作数；单元格编辑内容为 `操作符 + 右操作数`。
  - 未绑定列：单元格编辑内容为完整条件组，与条件分支节点对齐，支持标准条件行、`AND/OR` 组合及最多两层嵌套。
  - 每个未绑定列单元格默认创建一条空条件行；同层级新增第二条条件时，默认逻辑符为 `AND`。
  - 输入单元格默认仅显示条件摘要，点击后进入条件编辑器，不在表格中直接内联展开复杂控件。
  - 输入单元格为空表示该列在本行不参与命中判断，即通配语义。
- 输出列规则：
  - 输出列是节点自身输出字段，不强绑定响应 Schema。
  - 每列声明字段名与类型，供后续节点引用。
  - 输出单元格统一采用 `Value Editor(Fixed/Expression)`，默认仅显示值摘要，点击后进入值编辑器。
  - 某行命中后若某个输出单元格为空，则该输出字段返回 `null`。
- 命中语义：
  - 多行命中策略：首条命中即停止。
  - 同一规则行内，所有非空输入列按 `AND` 组合命中；需要 `OR` 时建议拆成多行。
  - 所有输入单元格均为空的规则行为无条件命中规则，推荐作为最后一行兜底；若出现在非最后位置，应视为强校验失败。
  - 若无命中且无兜底：输出完整输出列结构，全部为 `null`。
- 类型规则：
  - 行命中后若某输出列类型不匹配：严格失败（节点错误态 + 风险标记）。
  - 单元格内表达式失败同样按严格失败处理。
- 可解释性：
  - 记录命中行号、各输入列判定证据、未命中原因与输出列赋值结果。

### 4.11 函数节点（Function）
- 功能：以受控 JS 单文件模块完成复杂数据转换，补足表达式不适合处理的对象重组、数组处理与多步计算场景。
- 定位：高风险逃生口，仅用于流程图、表达式与决策表无法优雅覆盖的少数复杂场景，不作为常规主路径节点，更不是通用脚本入口或外部能力调用入口。
- UI：
  - 画布上需显式标记为高风险节点。
  - 编辑器顶部固定展示风险横幅，说明当前权限、环境状态、最后修改人、最后发布时间。
  - 中栏固定分为 `输入` 与 `代码编辑` 两段：`输入` 用结构化字段列表一体化维护 `字段名 / 类型 / 必填 / 说明 / 映射表达式`；`代码编辑` 为主区域。
  - `输入` 只支持扁平顶层输入项，但单个输入项本身可以是 `object` 或 `array`；字段名支持基于映射表达式结果自动补全，不支持批量勾选生成输入项。
  - 代码采用受控单文件 ESM 形态，必须且只能导出一个 `handler`，默认模板为 `export async function handler(input) { return {}; }`；允许在同文件内编写私有辅助函数、常量与局部工具逻辑。
  - 代码编辑器需支持语法高亮、lint、行号、错误定位、`input` 自动补全，以及平台白名单模块的导入提示与插入。
  - 右栏展示最近一次节点验证结果：成功态默认先显示原始返回 JSON，并可切换查看只读输出变量树；代码或输入变更后，右栏需提示“基于上次成功执行，当前已失效，需重新执行”。
- 输出约束：
  - 不要求用户预先手工声明完整输出 Schema；节点最近一次成功执行后，系统根据返回结果生成当前输出变量树，供下游节点引用。
  - 根返回值必须是 `object`，不允许直接返回标量或数组。
  - 代码、输入字段定义或输入映射变更后，保留上一次成功执行生成的输出变量树，但标记为“已失效”；重新执行成功后再刷新。
- 权限与环境约束：
  - 仅研发角色可编辑。
  - 非研发角色可只读查看源码、输入定义与最近运行结果，但不能修改。
  - 仅 Dev/Test 可修改。
  - Prod 只允许运行已审批版本。
- 运行与能力边界：
  - 执行语义采用轻异步模型，入口固定为 `async handler(input)`；允许 `await`，但不因此开放任意宿主 IO 能力。
  - 允许直接使用 ECMAScript 内建对象；额外平台能力通过受控静态 `import` 引入，且只能导入平台白名单模块。
  - 不开放 `fetch`、`process`、`Buffer`、文件系统、环境变量、动态 `import()`、相对路径/绝对路径导入等宿主运行时能力。
  - 采用平台统一的超时、内存与输出大小限制；首版不开放节点级自定义运行配额。
  - lint 或静态检查可提前发现的问题，应在编辑态即时提示；执行失败时右栏需展示错误类型、错误消息、源码行列号与简化堆栈。
- 审计与 Diff：
  - `Function` 版本 Diff 默认分三段展示：`依赖变化`、`输出变量树变化`、`源码 diff`。
  - `import` 增删改应在 `依赖变化` 区块内单独结构化呈现，不仅依赖源码文本 diff。

## 5. 决策表节点专项设计

### 5.1 节点配置 UI 结构
- 区域 A：列模型定义（输入列/输出列）。
- 区域 B：规则表格（行优先级、输入条件摘要、输出值摘要、有效状态、备注）。
- 区域 C：单元格编辑器（点击输入单元格进入条件编辑器，点击输出单元格进入值编辑器）；命中结果在节点验证结果与整流测试节点详情中展示。

### 5.2 规则行编辑体验
- 支持新增、复制、删除与拖拽排序；排序变更属于规则语义变更。
- 支持固定表头与固定行号，保证大表格下仍能稳定阅读和沟通命中行。
- 首版不提供行启停、批量启停与智能冲突分析；仅保留必要结构校验，如全空输入行位置错误、表达式非法、类型不匹配等。
- 首版不支持 spreadsheet 式批量填充、拖拽复制或公式下拉扩展。

### 5.3 验证与诊断
- 输入列逐列判定结果可视化（true/false/skip + 证据）。
- 命中行与未命中原因并排展示，并明确显示本次验证快照 ID。
- 输出列赋值追踪（值来源：Fixed/Expression、最终求值结果与写入值）。

### 5.4 稳定性与治理
- 决策表变更自动生成行级 Diff（新增、删除、条件变更、输出变更）。
- 提审时附带“潜在影响摘要”（命中覆盖变化、兜底风险）。

## 6. 版本与发布治理（多环境分级 + 发布申请 + 审批流 + 回滚）

### 6.1 环境分级
- Dev：策略设计与快速验证环境；允许从当前校验通过的 Draft 生成并替换 Dev 生效产物，无需审批。
- Test：联调、回归、发布前验证环境；只允许运行当前环境生效的决策流版本。
- Prod：正式生产环境；只允许运行审批通过且完成正式发布的决策流版本。

### 6.2 核心对象模型
- `Draft`：决策流的唯一可编辑态；每条决策流始终维护一个 Draft。
- `决策流版本`：由 Draft 生成的不可变快照，包含节点、连线、配置、Schema、校验结果与资源引用指纹。
- `发布申请`：针对某个 `Test` 或 `Prod` 环境、基于某个决策流版本发起的一次治理流程记录。
- `环境当前生效版本`：某条决策流在某个环境当前实际运行的版本。
- 对象关系：决策流版本是内容对象，发布申请是流程对象；一个决策流版本可以关联多条发布申请。

### 6.3 Draft 与决策流版本
- 用户在 `决策流` 页编辑的是 Draft，而不是直接编辑历史版本。
- 当 Draft 通过提审门禁后，用户可显式生成新的 `决策流版本`，进入后续治理流程。
- 历史版本永远只读；若用户希望基于某个历史版本继续修改，系统提供“从该版本重建当前 Draft”动作。
- 若当前 Draft 已存在内容，再次从历史版本重建时需给出确认提示，并允许覆盖当前 Draft。

### 6.4 版本与发布页面模型
- `版本与发布` 为一级菜单，但页面主体仍是 `决策流`。
- 首页先展示决策流列表，而非全站混合版本列表；每条决策流展示版本总数、`Test/Prod` 当前生效版本、待审批申请数、待发布申请数与最近发布时间。
- 进入某条决策流后，详情页采用“环境锚定 + 版本审查双栏”：顶部为 `Test / Prod` 双环境卡，下方左侧为版本列表、右侧为版本详情。
- 详情页默认选中最新版本；若最新版本不是当前 `Prod` 生效版本，右侧顶部需明确提示该版本与 `Test / Prod` 的关系，并提供跳转到当前生效版本的入口。
- 点击 `Test` 或 `Prod` 环境卡时，版本列表自动滚动并高亮该环境当前生效版本，右侧切换到对应版本详情；环境卡不作为列表筛选器。
- 版本列表以 `决策流版本` 为主体，默认按版本创建时间倒序展示；版本项突出版本号、创建时间、创建人与环境关系标签，如 `Test 当前`、`Prod 当前`、`曾发布`、`未发布`、`已回滚`。
- 版本详情采用固定顺序纵向分段，不使用 Tabs；顺序为 `版本摘要与动作 -> 与环境关系 -> 变更 Diff -> 资源指纹 -> 申请/发布记录`。
- 发布申请不在 `版本与发布` 详情页展开为待办列表；该页只展示申请摘要、最近申请、关联申请状态和跳转到 `审批中心` 的入口。

### 6.5 发布申请与审批流程
- `Dev` 不通过 `版本与发布` 页面作为主要操作入口；用户在决策流页完成验证后，直接“发布到 Dev / 运行并生效”。
- `Test / Prod` 统一通过 `版本与发布` 页面发起发布申请。
- 发布申请发起时不让用户自由选择目标环境，而是由当前版本的环境关系自动推导：尚未成功发布到 `Test` 的版本默认申请 `Test`；已成功发布到 `Test` 但尚未成功发布到 `Prod` 的版本默认申请 `Prod`。
- `Prod` 发布前强制要求同一版本已经成功发布到 `Test`；未经过 `Test` 的版本不出现或不允许 `Prod` 申请入口，也不能发布到 `Prod`。
- `Test` 发布申请首版自动审批通过，但仍生成完整申请记录，处理人显示为系统，并进入 `已自动通过 / 未发布`；系统不自动发布到 `Test`。
- `Prod` 发布申请首版采用单人审批通过；任一符合资格的审批人通过后，进入 `已批准待发布`。
- 审批通过不等于已上线；仍需在 `版本与发布` 中手动点击“发布到环境”，才真正替换该环境的当前生效版本。
- 申请创建表单只要求申请人填写 `版本说明 / 风险说明`，目标环境、版本号、项目与决策流等上下文只读展示。风险等级由系统计算默认值，申请人可以上调但不能下调。
- 创建申请时生成审批快照，冻结版本摘要、Diff 摘要、资源指纹摘要、校验结果、系统风险等级与最终风险等级；首版不包含回放证据引用。
- 审批中心列表默认进入 `待我处理`，并提供 `我发起的 / 已处理 / 全部` 快速筛选；`已批准待发布` 不进入 `待我处理`，发布待办回到 `版本与发布`。
- 审批动作只在申请详情页提供。通过时附加理由可选；驳回时驳回理由必填。首版不做评论流、补充材料状态、用户上传附件、批量审批或批量发布。
- 驳回和撤销都是终态。驳回后，申请人可复制原申请生成新申请；申请人只能在 `待审批` 状态撤销。
- 审批中心不承载发布确认、发布失败详情或重试入口，只展示是否已发布的极简状态摘要。最终发布、发布失败原因和重试均回到 `版本与发布`。

### 6.6 发布与回滚
- 环境卡承载环境级主操作，包括发布已审批版本到该环境、回滚当前环境。
- 版本详情承载版本级动作，包括为此版本发起 `Test/Prod` 发布申请、查看关联申请、查看发布记录、从该版本重建 Draft。
- `Test / Prod` 发布采用单页确认面板，而非多步向导；面板顺序展示目标环境、版本信息、审批状态、一致性校验结果、风险提示与最终确认按钮。
- 发布确认面板只在 `版本与发布` 承载，可从环境卡或版本详情中的可发布状态进入；`审批中心` 只提供关联版本和发布记录的普通文本链接。
- 回滚主入口位于“当前环境生效版本”上下文中，而不是在所有历史版本列表中默认高亮。
- 回滚本质为：将目标环境的 `当前生效版本` 切换到某个历史稳定版本；回滚后自动记录原因、操作者、影响范围与恢复时间。

### 6.7 Dev 生效模型（Draft vs Dev Active Build）
- Draft：策略师在 Dev 画布上的可变编辑态；保存 Draft 不影响对外 `dev` 调用。
- Dev Active Build：对外 `Dev Key` 调用的稳定运行态；仅在点击“发布到 Dev / 运行并生效”后生成并原子替换。
- Dev 无需审批，但仍必须通过页面级校验与资源可用性检查；生成失败不影响上一版 Dev Active Build 的可用性。

### 6.8 资源一致性与受保护资源
- 决策流版本生成时，需记录所引用资源定义的指纹（hash），作为后续审批与发布材料的一部分；系统内置画像源记录画像源标识与字段目录版本。
- 发布到 `Test/Prod` 时，若检测到审批后的可配置资源指纹与当前资源定义不一致，则阻止发布并要求重新发起发布申请。
- 资源本身不做用户可见版本；但只要某资源被任一 `Test/Prod` 当前生效决策流引用，即进入受保护状态。
- 受保护资源的行为字段不可原地修改；若需变更，只能复制为新资源，并在 Draft 中切换引用后生成新的决策流版本。

### 6.9 对外接入与环境路由（HTTP API）
- 接入形态：HTTP API；鉴权方式：API Key。
- API Key 策略：按环境区分，不绑定项目、调用方或接入应用；在 `数据与集成 > 接入设置` 中管理。
  - `Dev`：当前 Key + 备用 Key
  - `Test`：当前 Key + 备用 Key
  - `Prod`：当前 Key + 备用 Key
- 客户侧使用契约：
  - 客户 dev/CI：使用 `Dev Key`
  - 客户 staging/test：使用 `Test Key`
  - 客户生产：使用 `Prod Key`
- 环境选择：环境由 API Key 绑定确定；若为了兼容保留 `X-Env` 或等价参数，该参数必须与 Key 绑定环境一致，否则直接拒绝。
- 生效路由：执行服务根据 `(tenant_id, flow_id, env)` 查询环境生效指针并执行；`dev` 命中 `active_build_id`，`test/prod` 命中 `active_version_id`；若该环境尚未部署则返回明确错误（不回退到 Draft 或其他环境）。
- Key 轮换：每个环境支持生成备用 Key、复制完整 Key、提升备用 Key 为当前 Key、停用 Key；提升后原当前 Key 自动停用。
- 可追溯：决策日志与指标维度需记录 `env`、API Key 指纹、请求 ID、实际执行的 build/version ID、资源引用指纹摘要，以及当时的项目归属快照。

## 7. 数据与可观测

### 7.1 决策日志
- 执行面必须产出结构化执行日志，供客户或平台侧离线分析使用；控制台首版不提供日志检索页。
- 请求与运行身份字段：`request_id`、`tenant_id`、`flow_id`、`env`、`build_id/version_id`、API Key 指纹、当时项目归属快照、请求开始/结束时间、总耗时、最终状态。
- 决策结果摘要字段：最终响应摘要、命中的 `Response` 节点、错误码、错误原因摘要、超时/降级/外呼失败/通知失败标记。
- 节点执行摘要字段：实际执行路径、节点 ID/名称/类型、执行状态、耗时、关键输入输出摘要、错误原因、副作用摘要、资源指纹摘要。
- 日志不记录完整敏感请求体、凭据密文、完整外呼响应或完整通知内容；需要通过脱敏、截断、哈希或字段级白名单控制。
- 执行日志写入不应成为决策链路的同步阻塞点；日志写出失败不改变本次业务响应，但需产生平台内部错误指标和运维告警。

### 7.2 控制台回放边界
- 首版不提供 `回放调试` 一级菜单、请求检索、历史请求轨迹、节点历史输入输出展开、版本对比回放或异常请求转测试样例。
- 线上运行后的具体请求排查通过结构化执行日志进入离线分析体系完成。
- 画布态整流测试仍只服务当前 Draft 的临时测试，不用于线上历史请求复盘。

### 7.3 指标体系
- 当前阶段不提供 `实时监控` 控制台页面、监控看板或指标下钻链路。
- 执行面仍应采集基础执行指标，供内部运维、离线分析和未来可观测页面使用。
- 服务指标：QPS、延迟分位、错误率、超时率。
- 策略指标：各分支命中率、拦截率、放行率、空结果率。
- 节点指标：节点耗时、失败率、降级率、通知投递成功率。

### 7.4 审计合规
- 覆盖策略变更、发布、审批、权限变更、资源定义改动。
- 首版支持操作日志时间范围查询与详情查看，不做审计导出、证据包、留存策略或脱敏策略配置。

## 8. 权限与安全

### 8.1 RBAC 建议
- 只读成员：可查看决策流、版本、审批记录、资源与审计日志；后续若启用监控页面，也可查看监控指标。
- 编辑成员：可创建和编辑 Draft、配置普通节点、运行测试、提交发布申请。
- 发布成员：在编辑能力基础上，可在审批通过后执行环境发布与回滚。
- 审批成员：可处理 `Prod` 发布申请，不自动获得编辑或发布能力。
- 管理员：管理成员、角色、高风险能力和系统级配置。
- 高风险能力独立授权：`Function 编辑`、`凭据管理`、`连接器管理`、`名单数据维护`、`API Key 管理`、`权限管理`。

### 8.2 凭据与资源安全
- HTTP/通知凭据统一托管，节点配置不暴露明文密钥。
- 凭据采用“凭据对象 + 凭据版本”双层模型；对象承载名称、类型、用途说明、允许绑定资源类型、状态与当前 active 版本，版本承载密文内容与版本级元数据。
- 凭据类型按认证模板建模，首版可覆盖 `API Key`、`用户名/密码`、`OAuth2 Client Credentials`、`AppId/AppSecret`；同一凭据对象可被多个连接器复用。
- 凭据独立轮换：同一凭据支持多密钥版本，支持先录入新版本、后切换 active，也支持一键回滚 active 到历史版本；轮换不要求重新发布决策流版本。
- 使用审计：审计需记录凭据轮换与 active 切换（操作者、时间、前后版本、备注），并可反查两层影响范围：被哪些连接器引用，以及这些连接器被哪些 `Test/Prod` 当前生效决策流引用。
- 离线分析与轮换解耦：执行日志需记录实际使用的凭据版本或资源指纹摘要，避免凭据轮换后无法追溯当时运行上下文。
- 资源编辑边界：Draft 中只引用资源定义或系统内置能力；资源定义的编辑统一在 `数据与集成` 页进行，系统内置画像源不提供租户侧编辑。
- 受保护资源：资源为租户账户级共享定义；当被任一决策流的 `Test/Prod` 当前生效版本引用后进入受保护状态，影响运行行为的字段不可原地修改，需复制为新资源并随新版本发布完成引用切换。
- 外呼元信息注入（高级配置）：连接器可配置自动注入环境/请求 ID/版本等 header，并显式告知客户，便于客户侧分流与追踪；必要时可关闭以兼容对端限制。

### 8.3 执行安全
- 函数节点沙箱隔离，限制不可控能力。
- 关键操作（发布、回滚、权限修改、API Key 管理、凭据管理）强审计并可二次确认。

### 8.4 多租户隔离边界（MVP）
- 身份隔离：API Key 必须可解析 `tenant_id` 与绑定环境，所有数据与配置查询强制 `tenant_id` 过滤。
- 配置隔离：决策流、版本、权限、日志、审计、连接器/凭据等均按租户隔离（租户内可账户级共享）。
- 状态隔离：计数器/缓存等状态型 key 必须包含 `tenant + flow + env` 命名空间，避免串写；项目只是分类容器，不参与运行隔离。
- 资源隔离：建议按租户维度做配额与限流，避免单租户流量影响全站。

## 9. 非功能要求

### 9.1 性能
- 决策链路低延迟，支持高并发扩展。
- 节点执行需提供超时控制与降级机制。

### 9.2 可用性
- 控制面与执行面分离部署，减少相互影响。
- 执行服务支持多副本与故障切换。

### 9.3 可扩展性
- 节点插件化，便于新增行业能力。
- 数据源、通知通道、连接器可按租户扩展。

### 9.4 可维护性
- 配置与代码边界清晰（低代码优先、函数节点受控）。
- 日志、指标、追踪统一，便于定位故障。

## 10. 迭代路线图（MVP -> 增强）

### 10.1 MVP（首发）
- 11 类节点完整可用。
- 决策流大画布 + 三栏编辑器。
- 多环境分级 + 审批发布 + 回滚。
- 结构化执行日志、离线可解释、基础执行指标采集与审计；不提供 `实时监控` 控制台页面。

### 10.2 增强版（Phase 2）

- 决策表高级能力（规则冲突自动修复建议、覆盖分析）。
- 流量灰度发布与 A/B 实验。
- 策略效果评估闭环（收益对比、误杀漏判分析）。

### 10.3 平台化（Phase 3）
- 多行业模板市场（风控、运营、审批等）。
- 节点生态开放与第三方扩展。
- 私有化交付标准包与运维工具链。

## 附录 B：补充共识（2026-03-04 讨论沉淀）
- 对外接入：HTTP API + API Key；2026-05-22 讨论后调整为环境级 Key，不再采用每项目 Key。

- 凭据：采用“凭据对象 + 凭据版本”模型；支持先录入新版本、后切换 active，也支持回滚 active；同一凭据可被多个连接器复用；轮换不要求重发版本，执行日志记录实际使用的密钥版本以便追溯。
- 外呼：Dev/Test 默认真实执行（HTTP/Notify 不做平台级 dry-run）；平台建议提供幂等/去重键并在发布时给出风险提示；可高级配置自动注入外呼 header 元信息（如环境、请求 ID、版本号）并显式告知客户。
- 命名空间：变量引用底层仍绑定系统生成且不可编辑的 `namespaceKey`，与节点显示名解耦；界面上不直接暴露 `namespaceKey`，而以显示名 token 呈现引用。

## 附录 C：补充共识（2026-03-25 讨论沉淀）
- 画像源：2026-05-22 讨论后，MVP 调整为系统内置只读能力目录，不提供用户自定义画像源创建、运行配置、环境覆盖、凭据绑定、字段目录维护或资源级测试。

- `审计与合规` 首版只做操作日志检索和详情查看，不做跨页面跳转、证据包导出、留存策略、脱敏策略或权限报表。
- 首版不做 `回放调试` 一级菜单、请求检索、历史请求轨迹、版本对比回放或异常请求转测试样例。
- 执行面仍需产出结构化执行日志，用于客户或平台侧离线分析；控制台不提供日志检索页。

## 附录 G：补充共识（2026-05-22 控制台配置发布主链路）
- 当前阶段不展开 `实时监控` 控制台页面；MVP 一级菜单不包含 `实时监控`，但保留结构化执行日志和基础执行指标采集，为后续可观测能力提供基础。
- 决策流配置发布主线以 `注册防刷` 作为模板级样例，但不提供产品内置模板功能；用户仍从空白画布手工搭建。
- 样例主流程为 `Request -> Profile Query -> List(query) -> Counter -> Decision Table -> Response`。
- 主流程保持只读，不包含名单写入、通知投递或外部副作用；`List add/remove/refresh_ttl`、`Notify`、`HTTP`、`Function` 均作为高级节点或可选扩展。
- `Profile Query`、`List`、`Counter` 只产出事实数据，最终风险判定集中在 `Decision Table`。
- `Response` 默认采用单一返回结构，多返回结构作为用户显式升级能力保留。
- 主线依赖的 `画像源` 来自系统内置只读目录，`名单` 必须先在 `数据与集成` 准备完成；节点编辑器只引用内置画像源或已有名单。
- `画像源` 详情按 `基本信息 / 查询输入要求 / 字段目录 / 失败与降级说明` 组织；不提供创建、编辑、绑定凭据、环境覆盖、连通性测试或样例请求测试。
- `名单` 详情突出 `键类型 / 规范化规则 / 默认 TTL / 引用状态 / 受保护状态`，并支持单条 key 查询、新增和删除；名单数据全环境共享，新增和删除要求 `名单数据维护` 高风险能力；批量导入、运营清理和大规模审计检索放后续运营能力。
- 配置完成校验采用双层呈现：画布问题面板负责全局阻断项，节点右栏负责本节点最近一次验证结果。
