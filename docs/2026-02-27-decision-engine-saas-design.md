## 1. 产品定位、目标与非目标

### 1.1 产品定位

本产品是面向实时业务决策的通用决策引擎 SaaS，首发聚焦注册、登录、活动参与等账号风控场景。用户通过流程图配置事实查询、条件判断、决策表和响应映射，不需要为常规策略编写和发布业务代码。

### 1.2 核心价值

- **PRD-GOAL-001 直观表达**：用流程图和结构化节点表达决策路径，降低策略沟通与维护成本。
- **PRD-GOAL-002 快速迭代**：将策略从编辑、验证、生成版本到环境发布形成可重复闭环。
- **PRD-GOAL-003 可解释**：每次执行能够关联实际版本、执行路径、节点结果和最终响应。
- **PRD-GOAL-004 可治理**：版本、审批、发布、回滚、权限和审计形成一致治理链路。
- **PRD-GOAL-005 可扩展**：统一节点、表达式、资源和执行产物模型，支持后续增加行业能力。

### 1.3 当前非目标

- **PRD-NONGOAL-001**：不兼容独立规则集子图，不同时维护两套引擎形态。
- **PRD-NONGOAL-002**：MVP 不提供灰度发布、A/B 实验和策略效果归因。
- **PRD-NONGOAL-003**：MVP 不提供线上请求回放、历史请求转测试样例和控制台执行日志检索。
- **PRD-NONGOAL-004**：MVP 不提供用户自定义画像源。
- **PRD-NONGOAL-005**：MVP 不提供模板市场、第三方节点市场和节点 SDK。
- **PRD-NONGOAL-006**：MVP 不提供项目级、决策流级或环境级细粒度授权矩阵。
- **PRD-NONGOAL-007**：MVP 不承诺移动端或窄屏编辑体验。
- **PRD-NONGOAL-008**：MVP 不提供多路径并行执行、隐式汇合或循环流程。

## 2. 发布范围

### 2.1 P0：首条可运行、可发布的垂直切片

P0 以“注册防刷”样板为锚点，但不提供产品内置模板。用户从空白画布手工建立：

```text
Request
  -> Profile Query
  -> List(query)
  -> Counter
  -> Decision Table
  -> Response
```

P0 必须完成：

- **PRD-P0-001**：租户管理员能够登录控制台，并进入租户隔离的产品空间。
- **PRD-P0-002**：能够创建项目分类、决策流和唯一可编辑 Draft。
- **PRD-P0-003**：能够配置六类核心节点及其变量引用。
- **PRD-P0-004**：能够查看系统内置画像源目录，并创建按环境隔离的名单资源。
- **PRD-P0-005**：Counter 能够读取不含当前请求的历史窗口结果，并原子记录当前请求供后续调用使用。
- **PRD-P0-006**：能够执行到指定节点、运行当前 Draft 的整流测试，并区分成功、失败、降级和未到达。
- **PRD-P0-007**：能够从校验通过的 Draft 生成不可变 Flow Version，并生成 Dev 环境生效产物。
- **PRD-P0-008**：能够为同一 Flow Version 发起 Test 发布申请；Test 自动审批但不自动发布，发布成员必须手动发布。
- **PRD-P0-009**：客户系统能够通过 Test 环境 API Key 调用 Test 当前生效版本。
- **PRD-P0-010**：关键控制面操作进入审计基础链路，执行面产出结构化执行日志和基础指标。

P0 主链路不包含 HTTP、Notify、Function 或名单写操作。Counter 对当前请求的原子记录属于平台内部状态更新，并且在控制台验证模式中使用隔离的测试状态，不修改外部环境的生效状态。

### 2.2 P1：补齐完整 MVP

P1 必须补齐：

- **PRD-P1-001**：Derived Variables 和 Condition 节点。
- **PRD-P1-002**：HTTP 连接器、通道连接器、凭据及其环境绑定。
- **PRD-P1-003**：HTTP 和 Notify 节点。
- **PRD-P1-004**：List `add / remove / refresh_ttl` 操作及副作用安全控制。
- **PRD-P1-005**：租户成员、全局角色、高风险能力和完整 API Key 生命周期。
- **PRD-P1-006**：Prod 发布申请、人工审批、手动发布、失败恢复和回滚。
- **PRD-P1-007**：Function 节点及受控运行时。
- **PRD-P1-008**：完整审计查询、执行日志可靠写出、指标、限流和 MVP 硬化。
- **PRD-P1-009**：Response 多返回结构的显式升级能力。
- **PRD-P1-010**：完整 MVP 的端到端、性能、安全和故障验证。

### 2.3 Post-MVP

后续阶段包括：

- 实时监控控制台和指标下钻。
- 请求级回放和历史轨迹。
- 用户自定义画像源。
- 决策表冲突与覆盖分析。
- 灰度发布、A/B 实验和策略效果评估。
- 名单批量导入、大规模清理和运营工作台。
- 企业身份接入、细粒度授权、私有化交付工具链。
- 模板市场、节点生态和第三方扩展。

## 3. 用户角色与核心旅程

### 3.1 角色

- **租户管理员**：管理成员、全局角色、高风险能力、API Key 和系统级设置。
- **只读成员**：查看决策流、版本、申请、资源和审计记录。
- **编辑成员**：创建和编辑 Draft、运行验证、生成版本和发起申请。
- **发布成员**：将已满足治理条件的版本发布到目标环境并执行回滚。
- **审批成员**：处理 Prod 发布申请，不因审批角色自动获得编辑或发布能力。
- **研发成员**：在编辑能力基础上，可以被授予 Function 编辑等高风险能力。

同一成员可以拥有多个角色或能力，但系统不得默认将审批与发布能力绑定在一起。

### 3.2 核心旅程

#### 旅程 A：创建并验证注册防刷决策流

1. 准备 Test 环境名单。
2. 创建决策流 Draft。
3. 配置六节点主链路。
4. 通过节点验证和整流测试检查执行结果。
5. 修复画布问题面板中的阻断项。

#### 旅程 B：发布到 Test 并接入

1. 从 Draft 生成 Flow Version。
2. 发起 Test 发布申请。
3. 系统自动审批并形成申请记录。
4. 发布成员手动发布。
5. 客户使用 Test Key 调用当前生效版本。

#### 旅程 C：发布到 Prod

1. 同一 Flow Version 已成功发布到 Test。
2. 发起 Prod 发布申请。
3. 审批成员查看版本、Diff、资源解析摘要和风险信息。
4. 审批通过后，发布成员手动发布。
5. 发生问题时回滚到该环境历史稳定版本。

## 4. 核心领域对象

### 4.1 项目

- **PRD-DOMAIN-001**：项目只是决策流的轻量分类容器。
- 每条决策流最多属于一个项目，也可以未归类。
- 删除项目时，所属决策流回到未归类。
- 项目不承担权限、API Key、环境、资源或运行隔离。

### 4.2 决策流与 Draft

- **PRD-DOMAIN-002**：每条决策流始终有且只有一个当前 Draft。
- Draft 是唯一可编辑态。
- Draft 保存不改变 Dev、Test 或 Prod 的当前生效行为。
- Draft 必须具有递增 revision；并发覆盖必须被识别并显式处理。
- 历史 Flow Version 只读；用户可以基于历史版本重建当前 Draft。

### 4.3 Flow Version

- **PRD-DOMAIN-003**：Flow Version 是从某一 Draft revision 生成的环境无关、不可变产品配置快照。
- Flow Version 包含图、节点配置、输入输出契约、表达式引用、校验摘要和资源逻辑引用。
- 同一 Flow Version 可以先后进入 Test 和 Prod。
- Flow Version 不直接包含某一环境解析后的连接地址或当前凭据版本。

### 4.4 Compiled Artifact

- **PRD-DOMAIN-004**：Compiled Artifact 是 Flow Version 或 Draft revision 针对特定目标环境生成的不可变运行产物。
- Artifact 必须记录编译器版本、环境解析结果、资源指纹、节点映射和产物 hash。
- Dev Active Build 来自 Draft revision；Test/Prod Artifact 来自 Flow Version。

### 4.5 发布申请、部署与生效指针

- **PRD-DOMAIN-005**：发布申请是治理对象，部署是一次环境切换尝试，生效指针表示环境当前实际运行的 Artifact。
- 审批通过不等于已发布。
- 发布失败不得影响该环境上一生效产物。
- 同一决策流、同一环境同一时刻只能有一个生效 Artifact。

### 4.6 资源定义和凭据

- **PRD-DOMAIN-006**：名单、HTTP 连接器和通道连接器是租户资源定义；凭据是独立对象并具有版本。
- 可配置资源不向用户暴露独立资源版本，但必须保留变更历史和审计。
- 被 Test/Prod 当前生效版本引用的行为字段进入受保护状态，不得原地修改。
- 凭据 active 版本可以独立轮换，不要求重发 Flow Version。

## 5. 流程图和执行语义

### 5.1 拓扑约束

- **PRD-FLOW-001**：MVP 流程是无环、单路径执行的有向图，不支持隐式 Merge、并行执行或循环。
- Request：无入边，恰好一个出边。
- Response：恰好一个入边，无出边。
- Condition：恰好一个入边，多个具名出边。
- 其他节点：最多一个入边、最多一个出边。
- 每个 Condition 分支必须最终到达独立 Response。
- 不允许不可达节点、孤岛或悬空必需出口。
- 后续若需要汇合，必须通过显式 Merge 节点另行设计。

### 5.2 执行路径

- **PRD-FLOW-002**：每次请求只执行一条确定路径。
- Condition 按顺序判断，首个命中分支生效；未命中普通分支时进入显式兜底分支。
- Response 命中后立即结束执行。
- 未位于实际路径上的节点状态为 `NOT_REACHED`，不得被误报为失败。

### 5.3 节点执行状态

控制台和执行记录必须区分：

- `NOT_STARTED`
- `RUNNING`
- `SUCCEEDED`
- `DEGRADED`
- `FAILED`
- `NOT_REACHED`
- `SKIPPED`：仅用于明确由异常策略跳过的节点

### 5.4 变量可见性

- **PRD-FLOW-003**：节点表达式只能引用 Request 正式输入和当前节点前序可达节点的输出。
- 引用底层绑定稳定、不可编辑的 `namespaceKey`，不依赖节点显示名。
- 新复制节点必须生成新的 `namespaceKey`。
- 从历史版本重建 Draft 时应保留原稳定标识。
- 不允许无命名空间的模糊引用。
- `object` 可以整体引用或展开到字段；`array` 在变量面板中以整体为主，表达式可以使用受支持的数组函数。

### 5.5 缺失值和错误

- **PRD-FLOW-004**：字段存在但值为空，或当前运行结果中字段缺失，基础取值均返回 `null`。
- 对 `null` 执行不合法运算、类型不兼容、引用失效或表达式运行错误时，当前节点进入错误处理流程。
- 表达式不得隐式吞掉类型错误。

### 5.6 异常策略

- **PRD-FLOW-005**：所有可能失败的节点必须遵循统一异常策略模型。
- MVP 至少支持：
  - `FAIL_FLOW`：终止并返回平台系统错误。
  - `DEGRADE_WITH_NULL`：节点输出降级外壳或 `null`，流程继续。
  - `ROUTE_TO_FALLBACK`：仅适用于具有明确异常出口的后续扩展；MVP 不默认提供。
- 节点不得自行定义与全局模型冲突的失败语义。

## 6. 控制台信息架构

MVP 一级菜单：

1. `决策流`
2. `版本与发布`
3. `审批中心`
4. `数据与集成`
5. `组织与权限`
6. `审计与合规`

不设置独立项目管理、实时监控或回放调试一级菜单。

### 6.1 决策流

- 列表支持所有决策流、按项目和未归类视图。
- 详情包含大画布、节点库、节点编辑层、问题面板和整流测试工作台。
- Draft 编辑、节点验证和生成版本入口均位于决策流上下文。

### 6.2 版本与发布

- 页面主体是决策流。
- 详情以 Test/Prod 环境卡为锚点，同时展示版本列表和选中版本详情。
- 版本详情固定展示版本摘要、环境关系、Diff、资源解析摘要、申请和部署记录。
- 发布确认和回滚只在此页面执行。

### 6.3 审批中心

- 页面主体是审批流程记录。
- 支持 `待我处理 / 我发起的 / 已处理 / 全部`。
- 审批中心只执行通过、驳回和撤销，不执行最终发布和重试。

### 6.4 数据与集成

- 包含系统内置画像源、名单、HTTP 连接器、通道连接器、凭据和接入设置。
- Draft 只引用资源，不在节点编辑器旁路创建或修改资源。

### 6.5 组织与权限

- 管理成员、全局角色和高风险能力。
- 不提供自定义角色编辑器和细粒度权限矩阵。

### 6.6 审计与合规

- 提供操作日志查询和详情。
- 不提供执行日志查询、证据包导出、留存策略编辑或跨页面审计跳转。

## 7. Draft 编辑、验证和测试

### 7.1 编辑器

- **PRD-AUTHOR-001**：画布采用桌面宽屏体验，节点配置使用覆盖式三栏编辑层。
- 左栏：前序可达变量。
- 中栏：节点配置和“执行到此节点”。
- 右栏：当前节点最近一次验证结果。
- 节点配置修改实时更新前端 Draft，并通过 debounce 持久化。
- 后端保存必须基于 Draft revision，检测并发冲突。

### 7.2 Value Editor 与 Expression Editor

- **PRD-AUTHOR-002**：所有通用值输入使用 `Fixed` 或 `Expression` 两种模式。
- Fixed 按声明类型保存字面值，不把字符串自动解析为其他类型。
- Expression 使用文本和稳定变量 token 混合编辑。
- 编辑器至少反馈语法、类型和引用错误。
- 运行语义由统一表达式运行时定义。

### 7.3 静态问题面板

- **PRD-AUTHOR-003**：生成版本前必须通过统一静态门禁。
- 门禁至少包括拓扑、节点完整性、表达式、输入输出契约、资源引用、动态输出 Schema 状态和高风险要求。
- 阻断问题与警告必须区分。
- 每个问题必须能定位到对象和字段。

### 7.4 执行到节点

- **PRD-TEST-001**：系统基于当前已持久化 Draft 和 Request 测试样例执行到目标节点。
- 若目标节点不在本次实际路径，返回 `NOT_REACHED` 并展示已执行路径。
- Draft 变更后，旧验证结果标记失效。
- 节点验证结果不等同于整流测试结果。

### 7.5 整流测试

- **PRD-TEST-002**：画布态提供当前 Draft 的整流测试工作台。
- 输入可以从 Request 测试样例初始化，并在当前会话临时修改。
- 结果展示真实执行顺序、节点输入输出摘要、错误、降级和副作用摘要。
- Draft 变更后，清空旧测试结果和画布高亮。
- 测试结果默认只在当前控制台会话保留。

### 7.6 测试执行模式与副作用安全

- **PRD-TEST-003**：控制台节点验证和整流测试不得无提示地修改生效环境状态。
- List 和 Counter 在普通 Draft 测试中使用与 Dev/Test/Prod 生效状态隔离的测试命名空间。
- HTTP 和 Notify 在普通 Draft 测试中默认进入受保护模式；真实请求必须由具备相应能力的用户显式选择环境、二次确认并记录审计。
- Function 不开放任意宿主 IO。
- 外部 Dev/Test API 调用使用对应环境真实状态，不使用 Draft 测试命名空间。

## 8. 节点规范

### 8.1 Request

- **PRD-NODE-REQUEST-001**：每条流程有且只有一个 Request。
- Request 定义树形输入 Schema，支持 object 和 array。
- 字段包含名称、类型、是否必填、描述和测试样例。
- 未声明字段可以出现在原始请求中，但不得进入变量空间。
- Schema 校验失败返回统一平台错误。
- `rawRequest` 只存在于单次执行内存上下文，默认不得完整持久化。
- 正式变量命名空间为 `request`。

### 8.2 Response

- **PRD-NODE-RESPONSE-001**：所有 Response 共享一份流级输出契约。
- 单一返回结构是默认模式。
- P1 支持显式升级为公共字段加多个返回结构。
- 每个 Response 必须完整映射其适用契约的所有必填字段。
- 字段映射使用 Value Editor。
- 命中 Response 后终止主流程。
- 平台 `request_id/trace_id` 通过响应 Header 返回，不要求污染用户自定义响应体。

### 8.3 Derived Variables

- **PRD-NODE-DERIVED-001**：一个节点可以定义多个具名派生变量。
- 同节点变量彼此独立，只能引用上游，不能引用同节点内其他变量。
- 结果可以是标量、对象或数组。
- 任一变量求值失败时，节点按统一异常策略处理。

### 8.4 Condition

- **PRD-NODE-CONDITION-001**：Condition 使用有序普通分支和一个固定兜底分支。
- 普通分支支持标准条件行和最多两层条件组。
- 首个命中分支生效。
- 每个出口必须连接，并最终到达独立 Response。
- Condition 不支持分支后重新汇合。

### 8.5 List

- **PRD-NODE-LIST-001**：List 节点支持 `query / add / remove / refresh_ttl`。
- P0 只实现 query；P1 补充其余操作。
- 名单由单一规范化 key 组成，可配置默认 TTL。
- 名单数据按 `tenant + environment + list` 隔离；MVP 不提供跨环境共享名单。
- query 输入为空时返回未命中，并标记 `empty_input`。
- 输出包含 `success`、`operation`、`reason`、`key`、`hit`、`applied`、`expiresAt` 和 `ttlRemainingMs`。
- 写操作在 Draft 测试中使用测试命名空间；真实环境写入要求高风险能力。

### 8.6 Profile Query

- **PRD-NODE-PROFILE-001**：MVP 只支持系统内置画像源。
- 用户选择画像源、查询值和失败策略，不配置供应商、地址或凭据。
- 输出为 `success / degraded / reason / payload`。
- `payload` 保留内置画像源原始结构，不做跨画像源二次投影。
- 画像源字段目录由系统维护，并作为变量提示和版本元数据。
- 严格失败终止流程；允许降级时输出降级外壳。

### 8.7 Counter

- **PRD-NODE-COUNTER-001**：Counter 支持时间窗口计次和分组去重。
- 每个统计项配置名称、类型、窗口和 key 表达式。
- 对外环境执行时，Counter 必须原子完成：
  1. 读取当前窗口历史值；
  2. 将该值作为本次节点输出；
  3. 使用请求幂等标识记录当前事件。
- 因此输出不含当前请求，但当前请求会影响后续请求。
- 同一请求重试不得重复记录。
- Counter 状态按 `tenant + flow + environment + counter item` 隔离。
- Draft 测试使用独立测试状态。
- 当前节点输出保持按统计名称组织的数值对象；记录结果在执行细节中展示。

### 8.8 HTTP

- **PRD-NODE-HTTP-001**：HTTP 节点必须选择 HTTP 连接器，只允许配置相对路径和本次调用参数。
- 节点不得直接填写任意完整 URL 或明文凭据。
- 输出主结构为 `ok / statusCode / body`。
- `body` 的详细字段树来自声明 Schema 或最近成功验证形成的 Schema 快照。
- 被下游引用时，动态 Schema 必须处于有效状态才能生成版本。
- 响应头、重试、耗时和原始摘要用于诊断，不默认进入变量空间。
- 外呼必须遵循连接器的环境、安全、超时和响应大小限制。

### 8.9 Notify

- **PRD-NODE-NOTIFY-001**：Notify 是通用通知节点，选择通道类型和通道连接器。
- MVP 支持 Webhook、短信、纯文本邮件和飞书应用消息文本。
- 通知内容内联在节点配置中，随 Flow Version 冻结。
- 节点成功只表示供应商或连接器接受提交，不表示最终送达。
- 提交成功后流程继续，Notify 不向下游暴露业务输出。
- Draft 真实投递必须显式确认并审计。

### 8.10 Decision Table

- **PRD-NODE-DTABLE-001**：Decision Table 支持多个输入列和多个输出列。
- 输入列分为绑定列和未绑定列。
- 行内所有非空输入列按 AND 组合；需要 OR 时拆为多行或在未绑定列条件组中表达。
- 按行顺序首条命中即停止。
- 全空输入行是无条件命中行，只允许位于最后。
- 无命中且无兜底时，输出完整输出结构且各字段为 `null`。
- 输出列声明字段名和类型，单元格使用 Fixed 或 Expression。
- 类型不匹配或求值失败时严格失败。
- 验证结果记录命中行、逐列证据和输出赋值。

### 8.11 Function

- **PRD-NODE-FUNCTION-001**：Function 是高风险逃生能力，不作为常规策略路径。
- 仅具备 Function 编辑能力的用户可以修改。
- 代码使用受控单文件模块，禁止任意网络、文件、环境变量和宿主进程访问。
- 输入由结构化字段和表达式映射定义。
- 根返回值必须为 object。
- 输出字段树来自显式声明或最近成功验证形成的 Schema 快照。
- 配置或代码变化后，旧输出 Schema 标记失效；存在下游引用时不得带失效 Schema 生成版本。
- Function 必须受到超时、内存、输出大小和模块白名单限制。

## 9. 数据与集成

### 9.1 系统内置画像源

- **PRD-RESOURCE-PROFILE-001**：控制台提供只读目录、查询输入要求、字段目录和失败说明。
- MVP 不提供创建、编辑、凭据绑定、环境覆盖和资源级测试。
- 平台必须提供本地和测试环境可控适配器，以支持开发和自动化测试。

### 9.2 名单资源

- **PRD-RESOURCE-LIST-001**：名单按环境维护独立 key 集合。
- 资源定义包含名称、key 类型、规范化规则、默认 TTL、环境状态、引用状态和受保护状态。
- 控制台支持单 key 查询；P1 支持新增、删除和刷新 TTL。
- Prod 名单数据不得被 Dev/Test 调试隐式修改。

### 9.3 HTTP 连接器

- **PRD-RESOURCE-HTTP-001**：连接器定义服务边界、认证、公共请求头、默认超时、重试、安全限制和元信息注入。
- 公共元数据可以共享，但每个启用环境必须解析到明确环境绑定。
- Dev/Test 不得隐式继承 Prod 运行目标。
- 连接器必须显示最终 URL 和认证摘要，不展示明文密钥。
- 连通性测试属于高风险真实测试，必须二次确认和审计。

### 9.4 通道连接器

- **PRD-RESOURCE-CHANNEL-001**：通道连接器只供 Notify 使用，按通道类型建模。
- 环境绑定、凭据、超时、重试、供应商扩展参数和安全限制由连接器管理。
- 通知模板不作为独立资源。

### 9.5 凭据

- **PRD-RESOURCE-CREDENTIAL-001**：凭据采用“对象 + 版本”模型。
- 对象保存用途、认证模板、允许绑定资源类型、当前 active 版本和状态。
- 版本保存密文和版本元数据。
- 新版本可以先录入并验证，再切换 active。
- active 切换不要求重发 Flow Version，但执行日志必须记录实际使用版本指纹。
- 完整密文永不在控制台重新展示。

### 9.6 API Key

- **PRD-RESOURCE-APIKEY-001**：Dev、Test、Prod 各自维护环境级 API Key。
- Key 完整值仅在创建时显示一次；丢失时必须轮换。
- 生命周期包含 `NEXT / CURRENT / RETIRING / REVOKED`。
- 提升 NEXT 后，旧 CURRENT 进入 RETIRING 并保留可配置宽限期，不得立即自动失效。
- Key 只允许调用绑定环境当前已部署的决策流。
- 每次调用通过 `flow_id` 指定目标流。

## 10. 版本、审批、发布和回滚

### 10.1 版本生成

- **PRD-RELEASE-001**：只有通过阻断门禁的 Draft 才能生成 Flow Version。
- 版本生成必须冻结产品配置、输出 Schema、表达式引用、资源逻辑引用、校验摘要和创建者。
- 历史版本只读。

### 10.2 Dev Active Build

- **PRD-RELEASE-002**：保存 Draft 不改变 Dev 对外行为。
- 用户显式执行“发布到 Dev”后，系统编译当前 Draft revision 并原子替换 Dev Active Build。
- 编译或切换失败时，上一 Dev Active Build 继续可用。

### 10.3 Test 发布

- **PRD-RELEASE-003**：尚未成功发布到 Test 的 Flow Version 可以发起 Test 申请。
- Test 申请自动审批，处理人为系统，但必须生成完整记录。
- 自动审批后仍需发布成员手动发布。
- 发布成功后，Test 生效指针原子切换。

### 10.4 Prod 发布

- **PRD-RELEASE-004**：只有同一 Flow Version 已成功发布到 Test，才允许发起 Prod 申请。
- Prod 使用单人审批。
- 审批与发布可以由同一成员完成，但必须分别满足审批和发布权限。
- 审批通过后仍需手动发布。

### 10.5 资源一致性

- **PRD-RELEASE-005**：审批快照必须包含目标环境资源解析摘要和指纹。
- 发布前重新解析资源。
- 若行为资源指纹与审批快照不一致，阻止发布并要求重新申请。
- 凭据 active 版本变化不触发资源行为指纹不一致，但必须记录实际凭据版本。

### 10.6 发布失败和回滚

- **PRD-RELEASE-006**：部署必须具有明确状态和失败原因。
- 失败不得修改当前生效指针。
- 重试必须是显式动作并保持幂等。
- 回滚是将目标环境切换到历史成功 Artifact；回滚同样生成部署和审计记录。
- 同一决策流、同一环境的部署操作必须串行化。

## 11. 权限、安全和审计

### 11.1 权限

- **PRD-SECURITY-001**：MVP 使用租户全局角色和高风险能力。
- 高风险能力至少包括：
  - Function 编辑
  - 凭据管理
  - 连接器管理
  - 名单数据维护
  - API Key 管理
  - 权限管理
  - 真实外联测试
- 管理员默认拥有高风险能力，但 UI 中必须单独展示。
- 高风险操作必须二次确认和审计。

### 11.2 多租户与环境隔离

- **PRD-SECURITY-002**：所有控制面和执行面对象必须属于明确 tenant。
- 项目不参与隔离。
- List、Counter、API Key、Artifact、日志和限流必须使用各自明确的 tenant/environment 维度。
- Dev/Test/Prod 不得通过资源回退、测试状态或 Key 选择发生隐式串用。

### 11.3 外联安全

- **PRD-SECURITY-003**：HTTP 和 Webhook 必须防止访问平台禁止的网络目标。
- 必须控制协议、DNS 解析、跳转、响应体大小、Header、超时和重试。
- Dev/Test 的真实外联不能隐式使用 Prod 绑定。
- 明文凭据不得进入节点、日志或审计。

### 11.4 审计

- **PRD-AUDIT-001**：关键控制面变更必须产生不可修改的最小审计事件。
- 至少覆盖：
  - 决策流和 Draft 变更
  - 版本生成
  - 申请、审批、发布、失败和回滚
  - 资源、凭据和名单数据变更
  - API Key 生命周期
  - 成员、角色和高风险能力
- 最小审计事件必须与业务写入保持一致，后续可以异步补充 Diff 和影响摘要。
- Key、密文和完整请求体不得写入审计。

## 12. 外部执行 API 产品契约

- **PRD-API-001**：外部客户通过版本化 HTTP API 调用决策流。
- 环境由 API Key 决定，不允许客户端自由切换。
- 请求必须指定 `flow_id` 并提供业务输入。
- 未部署、鉴权失败、Schema 错误、限流、超时和节点系统失败必须返回稳定平台错误结构。
- 业务拒绝或放行属于用户自定义 Response，不应被映射为平台系统错误。
- 每次响应必须返回可关联的 `request_id`。
- 同一请求使用幂等标识重试时，不得重复记录 Counter 或重复执行受保护的幂等副作用。
- 平台必须定义请求体、响应体、节点数和执行时限上限。

## 13. 执行日志、指标与隐私边界

### 13.1 执行日志

- **PRD-OBS-001**：执行面产出结构化日志，但日志写出不得同步阻塞决策响应。
- 日志至少包含：
  - request、tenant、flow、environment
  - 实际 build/version/artifact
  - API Key 指纹
  - 开始结束时间、总耗时和最终状态
  - 实际执行路径
  - 节点状态、耗时、错误和降级摘要
  - 资源指纹和实际凭据版本摘要
  - 最终响应摘要
- 默认不保存完整 rawRequest、完整外呼响应、完整通知内容或密文。

### 13.2 指标

- **PRD-OBS-002**：至少采集 QPS、p50/p95/p99、错误率、超时率、节点耗时、降级率、外呼失败率、队列积压和日志丢弃风险。
- MVP 仅用于内部运维，不提供客户控制台指标页。

## 14. 非功能要求与产品限制

### 14.1 性能和容量

- **PRD-NFR-001**：六节点纯平台链路的额外处理开销目标为 p95 不超过 50ms，不含外部画像源和客户连接器网络耗时。
- **PRD-NFR-002**：参考 P0 注册防刷链路在标准测试适配器下，端到端 p95 目标不超过 200ms。
- **PRD-NFR-003**：执行 API 默认 deadline 为 1 秒；超过限制返回稳定超时错误。
- **PRD-NFR-004**：MVP 默认限制：
  - 请求体不超过 256 KiB
  - 响应体不超过 256 KiB
  - 单流程不超过 100 个节点
  - Decision Table 不超过 1000 行
  - Function 输出不超过 256 KiB
- 限制必须可配置，但不得由普通租户绕过。

### 14.2 可用性

- **PRD-NFR-005**：执行面月度可用性目标不低于 99.9%。
- **PRD-NFR-006**：控制面故障不得中断已经缓存并生效的执行产物。
- **PRD-NFR-007**：发布失败不得影响上一生效版本。
- **PRD-NFR-008**：控制面数据恢复目标为 RPO 不超过 5 分钟、RTO 不超过 60 分钟；最终以生产部署方案验证。

### 14.3 可维护性和兼容

- **PRD-NFR-009**：节点配置、Flow Version 和 Artifact 必须携带 Schema/Compiler 版本。
- **PRD-NFR-010**：升级必须提供向前迁移或明确拒绝策略，不得静默改变历史版本语义。
- **PRD-NFR-011**：TypeScript 编辑态校验和 Go 运行时必须由共享语义规范与固定测试语料对齐。

## 15. 完整 MVP 验收

完整 MVP 达成时，必须满足：

1. 11 类节点全部可配置、校验和运行。
2. 六节点注册防刷链路能够通过连续请求验证 Counter 历史统计闭环。
3. Condition 能形成互斥分支，并由独立 Response 结束。
4. Draft 测试不会无提示污染生效环境状态。
5. Flow Version、环境 Artifact、部署和生效指针关系可追溯。
6. Test 自动审批、Prod 人工审批、手动发布和回滚均可端到端验证。
7. API Key 双 Key 轮换存在重叠期，旧 Key 可以按策略退出。
8. 资源指纹变化会阻止未经重新审批的发布。
9. 凭据轮换不要求重发版本，并能追溯实际使用版本。
10. Function 无法访问禁止的宿主能力，并受到资源限制。
11. 多租户、环境隔离、SSRF、防重放和权限测试通过。
12. 审计、执行日志和指标在依赖故障情况下具有明确降级与补偿行为。
13. 所有 P0/P1 要求均由 Change Framework 和测试覆盖矩阵追踪。

## 16. 术语表

- **Draft**：决策流唯一可编辑配置。
- **Flow Version**：环境无关的不可变产品配置快照。
- **Compiled Artifact**：针对目标环境生成的不可变运行产物。
- **Dev Active Build**：由 Draft revision 编译并在 Dev 当前生效的 Artifact。
- **发布申请**：审批与治理记录。
- **Deployment**：一次将 Artifact 切换到环境的尝试。
- **Active Pointer**：环境当前实际运行 Artifact 的权威指针。
- **资源指纹**：环境解析后行为配置的规范化 hash。
- **凭据版本指纹**：实际运行使用的密钥版本摘要。
- **节点验证**：从 Request 样例执行到指定节点。
- **整流测试**：对当前 Draft 执行完整实际路径。
- **测试命名空间**：与 Dev/Test/Prod 生效状态隔离的 Draft 验证状态空间。
